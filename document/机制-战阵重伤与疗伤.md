# 机制 · 战阵重伤与疗伤

> 版本：v2.21.0 ｜ 对应代码：`js/data.js`（`DBATTLE.INJURY` / `AUTO_MIN_HP_PCT`）、`js/engine.js`（`discHpPct` / `discInjured` / `discHealCost` / `healDisciple` / `dbattleSyncHp` / `dbattleInjureUnit`）、`js/state.js`（读档校验）、`js/ui.js`（信徒卡片 / 战阵伤兵区）、`js/main.js`（`disc_heal`）

## 1. 目标与口径

战阵不再允许「倒下后立刻满血再战」。信徒生命归零即视为重伤：自动下阵、暂时失去所有上阵资格，必须由玩家主动消耗资源恢复。恢复只能消耗灵力与低阶丹药，**没有任何定时或自然自愈**，灵力见底就彻底停摆。

v2.21.0 起，战阵也**不再在通关时回满生命**：剩余生命会跨关卡、跨动作、跨读档延续，只有疗伤能把生命抬回 100%。

与玩家自身疗伤（`CONFIG.HEAL_SPIRIT_COST` + `healWithSpirit()`）完全分离：不共用数值、不共用状态、不互相触发。

## 2. 致伤与自动下阵

| 步骤 | 行为 |
| --- | --- |
| 生命归零 | `dbattleEnemyStrike` 把单位标记为倒下，调用 `dbattleInjureUnit(u)` |
| 标记重伤 | 信徒实例写 `inst.injured = true`（跟着信徒走） |
| 自动下阵 | 立刻清空 `state.dbattle.lineup[u.slot]`，不留幽灵队员 |
| 场上无人 | 沿用现有失败流程 `dbattleLose()`：不扣资源、不掉关，释放动作槽 |
| 自动连战 | 下一场以当前编成为准；重伤者已不在编成里，不会带伤连战 |

战报追加「重伤倒下，自动下阵」；见闻提示可在战阵 / 信徒面板疗伤。

## 2.1 生命延续（v2.21.0）

| 场景 | 生命处理 |
| --- | --- |
| 通关 | **不回满**，按战斗结束时剩余比例写入信徒实例 |
| 失败 | 倒下的信徒为 0（重伤），存活者按剩余比例保留 |
| 自动连战进入下一关 | 沿用上一关剩余生命重新入场 |
| 停止后再挑战 / 扫荡以外的重复挑战 | 同上，不会因重开战阵回血 |
| 离开战阵面板再回来 | 战斗本身仍在跑；生命每帧写回实例，切回面板看到的仍是当前值 |
| 切换动作中止后再挑战 | `dbattleReset()` 先同步生命再清场，重开不回血 |
| 读档重进 | `inst.hpPct` 落盘，读档按上次剩余比例入场 |
| 扫荡 | 不进入战斗，也不改变任何信徒生命 |

- 生命以**比例** `inst.hpPct`（0~1）保存，缺失 = 满血；最大生命变化（战修 / 光环 / 编成）后仍按比例换算，避免绝对值溢出。
- 只有疗伤会把 `hpPct` 删除（即回满）；战斗、通关、失败、读档都不会自行回血。
- 自动连战血线：通关结算后若**任一在场信徒低于 25% 生命**，暂停连战并提示；手动挑战不受限制。取舍是「宁可少打一关，也不自动把残血信徒送进下一关导致重伤」。

## 3. 重伤期间的锁定

- **战阵**：`dbattleCanUse` / `dbattleValidateLineup` 拒绝并清空重伤信徒；编成下拉不再列出。
- **任务上阵**：`assignDisciple` 拒绝并提示；任务席位下拉不再列出。
- **朝代职位**：`assignDynastyPost` / `discAvailableForPost` 拒绝并提示；职位下拉不再列出。
- 遣散仍然允许：重伤信徒可以被遣散（`removeDisciple` 正常解除任务 / 职位 / 战阵引用）。
- 读档时，旧档残留的重伤信徒任务 / 职位引用一律忽略，战阵位由 `dbattleValidateLineup` 清空。

## 4. 疗伤价格

| 项 | 规则 |
| --- | --- |
| 计费方式 | 按缺失生命比例：每 1% 最大生命 `0.6` 灵力 |
| 从 0 回满 | 100% × 0.6 = **60 灵力** |
| 低血疗伤 | 未重伤但未满血也可以疗伤，按实际缺失比例计费（如 40% 生命 → 约 36 灵力），一次回满 |
| 单次封顶 | **200 灵力**（`DBATTLE.INJURY.SPIRIT_CAP`） |
| 丹药 | 每次疗伤额外消耗 **1 枚聚气丹**（`pill_juqi`，既有低阶丹药，不新增道具） |
| 资源不足 | 灵力不足 / 丹药不足时不扣任何资源，见闻提示具体原因与获取途径（「无法疗伤」） |
| 自然恢复 | **无**。不做定时回血、不做离线恢复 |

> 只有生命归零（0%）才是 60 灵力的满额疗伤；普通残血按实际缺失比例收费，但同样需要 1 枚聚气丹。公式对未来的「非致命受伤」同样适用。

## 5. 界面

- **信徒仓库卡片**：未满血时显示「生命 xx%」标签（低于 35% 变红），并给出疗伤按钮与费用预览；重伤时整张卡红边 + 标题旁「重伤」标识，状态行显示「重伤，需疗伤 · 生命归零，暂不可上阵」；资源不足时按钮变暗并标注「灵力不足 / 缺聚气丹」，点击仍会给出提示。
- **战阵面板**：编成槽显示当前生命（如 `30 / 75`）与对应血条，低血槽位橙色描边；编成下方「伤兵与低血 · 需疗伤 N 位」区逐行列出所有未满血信徒的品阶 / 职业、生命百分比、费用与疗伤按钮；槽位在倒下时已变为空缺。
- **资源不足提示**：伤兵区在缺灵力 / 缺丹药时显示一条说明——灵力靠自然凝聚（聚灵阵 / 洞天加速），聚气丹可炼丹（聚气草×2 + 草药×1）、市集·丹药阁购买或锁妖塔每 5 层掉落；并明确「重伤不会自然恢复」，避免玩家误以为可以等回血。
- **任务 / 职位下拉**：重伤信徒直接不出现在候选中，从入口上就不可选。
- 所有疗伤按钮统一 `data-act="disc_heal" data-uid="..."`，走既有 `setHTML` 签名重绘；没有把重伤状态写进会被重绘覆盖的 DOM。

## 6. 存档

- 字段：信徒实例上的 `injured: true` 与 `hpPct`（0~1）；**没有就视为健康 / 满血**，旧档无需迁移。
- 不另开重伤表，也不在 `state.dbattle` 里存名单：信徒被遣散 / 化道消耗 / 合成清理时实例消失，标记与残血随之消失，不会漂移出孤儿记录。
- `mergeState` 校验：
  1. 只有明确的 `injured === true` 或 `hpPct <= 0` 才标记重伤；
  2. `0 < hpPct < 1` 保留为残血（最低 0.01），大于等于 1 或缺失视为满血；
  3. 重伤信徒不再恢复任务席位与朝代职位引用；
  4. 战阵 `lineup` 中的重伤 uid 由引擎读档校验清空。

## 7. 与现有系统的边界

| 系统 | 关系 |
| --- | --- |
| 通关回血 | 已取消。任何非扫荡的战斗流程都不回血，只剩疗伤一条恢复途径 |
| 自动连战 | 通关后任一在场信徒低于 25% 生命即暂停并提示；手动挑战不受限制 |
| 玩家疗伤 | 完全独立：`CONFIG.HEAL_SPIRIT_COST` 与 `healWithSpirit()` 不改动 |
| 灵力 | 沿用现有灵力资源；疗伤只扣灵力，不新增货币 |
| 丹药 | 只消耗既有 `pill_juqi`；不新增物品，不影响炼丹产出 |
| 离线 | 战阵本身不参与离线结算；重伤也不会离线自愈 |
| 市集 | 完全未改动 |

## 8. 扩展方式

1. 若要新增致伤来源（例如事件 / 副本），扣减 `inst.hpPct` 并在归零时写 `inst.injured = true` 即可复用全部锁定与疗伤逻辑；
2. 若要支持战斗外缓慢恢复，只需在 `tick` 中抬高 `hpPct`——但当前设计明确不做；
3. 更换疗伤丹药只改 `DBATTLE.INJURY.PILL`，UI 与提示会自动读取。
