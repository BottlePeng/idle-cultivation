# 机制 · 世界（洞天营造）

> 参考《梅尔沃放置》的城镇（Township）机制设计：用资源营造建筑 → 建筑持续被动产出 → 人口提升整体效率。
> 在本作中改编为「洞天营造」：修士开辟一处洞天福地，招揽凡民与弟子，靠建筑维持香火与运转。

---

## 1. 概述

世界是一个**不占用动作槽**的常驻系统。玩家在「🏯 世界」面板中营造 / 升级建筑，建筑随时间**被动产出**资源，人口越多效率越高。

- 与灵植相同，世界属于**后台被动推进**：不占用动作槽，可与任何动作同时进行，离线同样结算。
- 营造是**瞬时操作**（点击即完成），没有建造队列与建造时间。
- 产出分两类：
  - **洞天内部资源**：粮食 🌾 / 木材 🌲 / 石料 ⛰️（存在 `state.world.res`，有容量上限）；
  - **全局资源**：灵石 💰 / 灵力 🌀 / 星砂 🌠（直接进入全局资源池，与挂机所得同源）。

> **图标约定**：本面板统一使用 Unicode 6.0 及更早的 emoji。`🪵`(U+1FAB5) 与 `🪨`(U+1FAA8) 属于 Emoji 13，Windows 10 的 Segoe UI Emoji 不含字形，会渲染成空心方框，故木材/石料改用 `🌲` / `⛰️`。

## 2. 数据结构

```
state.world = {
  buildings: { farm: 0, lumber: 0, ... },   // 建筑 id → 等级（0 表示未建造）
  pop: 0,                                   // 当前人口（浮点数，显示时取整）
  res: { food: 0, wood: 0, stone: 0 }       // 洞天内部资源存量
}
```

- `defaultState()` 初始给 `farm:1 / lumber:1 / house:1`、`pop:2`、`res:{food:120,wood:40,stone:20}`，保证开局能自转。
- `mergeState()` 按 `BUILDINGS` 裁剪（已删除的建筑等级直接丢弃），建筑等级不设上限、原样保留，资源钳制到按当前建设度算出的 `worldCap()`，人口钳制到当前人口上限。

## 3. 全局参数（`WORLD`）

| 键 | 值 | 含义 |
| --- | --- | --- |
| `BASE_POP_CAP` | 4 | 无民居时的人口上限 |
| `FOOD_PER_POP_MIN` | 2.5 | 每个居民每分钟消耗粮食 |
| `POP_GROWTH` | 0.003 | 有粮且净收益非负时，每秒向人口上限逼近的比例 |
| `POP_DECAY` | 0.002 | 断粮时人口每秒流失比例 |
| `EFF_BASE` | 0.3 | 人口为 0 时保留的基础效率 |
| `CAP.food/wood/stone` | 2000 / 1200 / 1200 | **建设度 1 时的基础仓储上限**，实际值见 `CAP_GROW` |
| `CAP_GROW` | 0.4 | 每点建设度，仓储上限相对基础值 +40%（`worldCap()`） |
| `COST_MUL` | 1.18 | 每级造价倍率（建筑等级无上限，造价指数增长） |

> **仓储上限 = 基础值 × (1 + 0.4 × (建设度 − 1))**，由 `worldCap(level)` 统一计算（`js/data.js`）。
> 建设度 1 时木/石各 1200，建设度 30 时约 1.5 万，建设度 500 时约 24 万。
> 这样做的原因是造价按 `1.18^等级` 指数上涨：若仓储固定为 1200，后期会出现"单级造价 > 仓储上限"而无法继续升级的死锁。

## 6. 公式

### 6.1 建设度

```
建设度 = 1 + Σ 所有建筑等级        // 空场为 1，用于解锁建筑
```

### 6.2 人口上限与效率

```
人口上限 = BASE_POP_CAP + Σ(民居等级 × 4)
人口效率 = EFF_BASE + (1 - EFF_BASE) × min(1, 人口 / 人口上限)
```

人口满员时效率 100%，无人时保留 30%——避免"人口清零 → 产出归零 → 永远无法恢复"的死锁。

### 6.3 每分钟产出

```
产出(资源) = 建筑基础产出 × 建筑等级 × 人口效率 × 60
粮食消耗   = 人口 × 2.5 /分
```

### 6.4 人口增减（`worldTick`）

| 条件 | 行为 |
| --- | --- |
| 粮食 > 0 且 粮食净额 ≥ 0 | 人口向上限逼近：`pop += (cap - pop) × 0.003 × dt` |
| 粮食 = 0 且 净额 < 0 | 人口流失：`pop -= pop × 0.002 × dt` |
| 粮食 > 0 但净额为负 | **人口维持**，消耗存粮（给玩家反应时间） |

> 断粮不会立刻清空人口，存粮能撑一段时间；只要补上灵田，人口就会回升。

### 6.5 营造造价

```
首建(0→1, 仅 req ≤ 1 的建筑) = floor(首建造价.灵石)   // 只收灵石，不耗木材/石料
首建(0→1, 其余建筑)          = floor(首建造价)         // 三资源照收
升级(lvl→lvl+1)              = floor(首建造价 × 1.18^lvl × (1 − 营造司减免))
```

> **仅「开局可建」的资源建筑（req ≤ 1：灵田 / 民居 / 伐木坊 / 招贤殿 / 引力塔）首建免材料**。
> 洞天开局没有任何木/石产出（木材由伐木坊被动产出、石料由采石场产出），
> 只有让这几座首批建筑免材料，才不会陷入"没有木石 → 建不了产木石的建筑 → 永远没有木石"的死锁。
> 采石场（req 2）等其余建筑首建仍需木/石，这正是需要先用产木建筑攒料的目标。

营造司减免 = `min(0.60, 营造司等级 × 1.5%)`，由 `worldBuildCost()` 统一计算，建造扣费与界面显示取同一口径。

灵石从全局资源池扣除，木材 / 石料从洞天仓储扣除。

## 7. 引擎接入

| 接入点 | 说明 |
| --- | --- |
| `worldTick(dt)` | 在 `tick()` 内紧随 `passiveTick` 调用，因此**离线快进同样生效** |
| `worldBonus(key)` | 读取加成型建筑汇总，供各系统加成通道使用 |
| `worldBuildCost(b, lvl)` | 折后造价（含营造司 / 铭文池减免），`buildBuilding` 与 UI 共用 |

`worldBonus` 可用通道（100 种建筑共用 17 个通道，同通道的加成线性相加）：

加成叠加口径：

```
sellPrice      = 价值 × SELL_RATIO × (1 + 阵法 sell) × (1 + 商行/茶肆 等)
灵石收益       = 基础 × (1 + 阵法 gold + 酒坊/集市广场 等)
xpMul          = 境界/阵法/五行 × (1 + 书院/建木台 等)
xpMul(打坐)    = 境界/悟性/阵法 × (1 + 书院类) × (1 + 静心堂/虚空门 等)
攻击           = 基础 × (1 + 阵法) × (1 + 演武场 + 锻坊/岩浆炉 等)
防御           = 基础 × (1 + 阵法) × (1 + 演武场 + 玄龟壁/磐石堡 等)
命中           = 基础 × (1 + 阵法) × (1 + 藏兵阁/箭坊 等)
闪避           = 基础 × (1 + 阵法 ev + 蜃楼)
生命上限       = 基础 × (1 + 阵法 hp) × (1 + 药庐/镇岳坛 等)
灵力凝聚       = SPIRIT_PER_SEC × (1 + 阵法 spirit + 龙宫/灵灯阁)
脱战回血       = 上限 × 3% × (1 + 阵法 regen + 潮闸/水镜台)
动作速度乘子   = 境界 × (1 + 疾风阵 + 风阵坊/官道 等)
灵植生长       = 基础 × (1 + 阵法 growth + 药圃/树屋 等)
掉落率         = 基础概率 × (1 + 阵法 drop + 宝库/古墓 等)，最终钳制到 1
精通经验       = 动作经验 × 0.6 × (1 + 阵法 mastery + 藏经阁 等)
建造成本       = 首建造价 × 1.18^lvl × (1 − min(0.6, 铭文池 + 营造司))
灵力支出       = 穿越星球吸收件数 × 0.5
```

> 灵力是「疗伤（25 点/次）/ 星球吸收」共用的资源池；星球占动作槽运行，吸收时按件扣 0.5，
> 不足则进入「灵力不足，等待中」并原地等待，不会出现负值。

## 8. 界面

- 侧栏最底部新增「🏯 世界」按钮，副标题显示「洞天 · 建设度 N」。
- 面板自上而下：建设度条 → 5 个数据块（人口 / 粮食 / 木材 / 石料 / 人口效率）→ 被动产出胶囊行 → 「地脉 · 地形」筛选条 → 建筑卡网格。
- 地形筛选条：`🗺️ 全部 100` + 8 个地形胶囊（含数量角标）；未达门槛的地形胶囊半透明并标注 `Lv.N`，但仍可点开预览该地形的建筑链。选中态持久化在 `state.ui.worldTerrain`。
- 建筑卡显示等级 `Lv.x / 30`、效果说明、造价按钮；「全部」视图下额外显示所属地形角标；门槛不足或资源不足时按钮置灰。
- **动态数值全部走 `data-w` / `data-wr` 占位节点**，由 `updateWorldState()` 增量刷新（遵守"高频数值不进 HTML"的约定，避免按钮闪烁）。
- 世界面板底部保留当前动作条，切换面板不会丢失进行中的动作。

## 9. 数值取向与后续扩展

- 建筑按地形成链：每条链都从「本命资源」起步（灵田 / 伐木坊 / 采石场 / 灵脉井），保证任意地形都能独立自转。
- 建筑等级**不设上限**：加成随等级线性叠加，造价按 1.18 倍指数增长，形成"越高越贵"的自然软上限，由资源产出速度而非硬上限决定节奏。
- 建筑门槛按建设度递增（1 → 98），每个地形内部约 8～10 点建设度解锁一档。
- 新增建筑只需在 `BUILDINGS` 追加一条并指定 `terrain`：`out` 走资源键、`bonus` 走 `worldBonus` 通道，UI 与存档自动兼容（`mergeState` 按表裁剪、地形筛选自动校验）。若新增 `bonus.key`，需在 `buildingEffect()` 的标签映射里补一行中文名，并在引擎对应接入点叠加 `worldBonus('新key')`。
- 新增地形只需在 `TERRAINS` 追加一条（`terrainReq` 会自动取该地形最低门槛）。
