# 机制 · 背包系统

> 相关代码：`js/data.js`（`ITEMS`、`CONFIG.INV_SLOTS/INV_SLOT_*`）、`js/engine.js`（`invCap/invSlotPrice/buyInvSlot/invCount/invHas/invSlotsUsed/invFull/invCanAdd/invAdd/invRemove/sellItem`）、`js/ui.js`（`renderBag/updateInvQty`）、`js/main.js`（`invup/invslot/filter/togglesell/sell/sellall`）

背包是**资源与物品的中枢**：采集、炼制、战斗掉落的产物都汇入背包，再由使用 / 装备 / 出售分流。v2.13.0 起支持**灵石扩容**。

---

## 1. 容量模型

**背包容量以「物品种类数」计**（而非总数量）：

```
invCap()       = min(INV_SLOT_MAX, INV_SLOTS + state.invSlots × INV_SLOT_STEP)
invSlotsUsed() = 数量 > 0 的物品种类数
invFull()      = invSlotsUsed() >= invCap()
invCanAdd(id)  = 已有该物品 ? true : invSlotsUsed() < invCap()
```

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `INV_SLOTS` | 100 | 基础容量 |
| `INV_SLOT_STEP` | 2 | 每次扩容增加格数 |
| `INV_SLOT_MAX` | 220 | 容量硬上限（60 次扩容） |
| `INV_SLOT_COST_BASE` | 300 | 第 1 次扩容价格 |
| `INV_SLOT_COST_GROW` | 1.14 | 每次扩容后的价格倍率 |

> **所有容量读取点统一走 `invCap()`**，禁止再直接引用 `CONFIG.INV_SLOTS`（扩容前有 5 处硬编码读取点，已全部替换：`invFull/invCanAdd/invAdd`、锁妖塔奖励空位判断、签到待入仓空位判断、侧栏与背包面板计数）。

- **同类堆叠**：同一物品 id 只占 1 格，数量可无限叠加（`state.inv[id] = 数量`）。
- 采集循环中若产出的物品是**新种类**且背包已满 → 动作进入「等待」而非中断（见 [动作槽与离线收益](./机制-动作槽与离线收益.md)）。

## 2. 背包扩容（v2.13.0）

### 2.1 公式

```
invSlotPrice(n) = max(1, floor(300 × 1.14^n))      // n = state.invSlots
容量(n)          = min(220, 100 + 2n)
```

- 每次购买：扣灵石 → `state.invSlots += 1` → 容量 +2。
- 达到 220 格后价格返回 0，按钮替换为「容量已满」。
- 存档字段：`state.invSlots`（扩容次数，整数），旧档缺失按 0，异常值夹到 `[0, 60]`。

### 2.2 价格曲线

| 已购次数 | 容量 | 下一次价格 |
| --- | --- | --- |
| 0 | 100 | 💠300 |
| 5 | 110 | 💠578 |
| 10 | 120 | 💠1,112 |
| 15 | 130 | 💠2,141 |
| 20 | 140 | 💠4,123 |
| 25 | 150 | 💠7,939 |
| 30 | 160 | 💠15,285 |
| 35 | 170 | 💠29,430 |
| 40 | 180 | 💠56,665 |
| 45 | 190 | 💠109,104 |
| 50 | 200 | 💠210,070 |
| 55 | 210 | 💠404,472 |
| 60 | 220 | 已满 |

- 全部 60 次累计约 **556 万灵石**。
- 曲线理由：
  - 首次 300 灵石，开局卖几组鱼/木即可买到，不会「早期买不起」；
  - 1.14 的倍率低于洞天建筑的 1.18，避免扩容比建设更贵；
  - 前 10 次总价仅约 6,000，能快速缓解新手期物品种类膨胀；
  - 后 20 次单价进入十万~百万级，与化神/炼虚期的洞天与战斗灵石产出匹配，后期仍有明确消耗目标。
  - 上限 220 略高于当前全部物品种类数 217，满容量后玩家可收集齐所有物品，不会出现「永远差几格」的死角。

### 2.3 为什么是「格数」而不是「堆叠上限」

- 现有所有系统（`invAdd/invCanAdd`、签到待入仓、锁妖塔奖励、市集购买）都按「种类数」判断空位，改为「数量上限」需要改动全部调用点与存档语义，风险高。
- 扩容格数只影响 `invCap()` 一个函数，改动面最小，且与现有「背包满 → 动作原地等待」的行为完全兼容。

## 3. 物品类型（`ITEMS[].type`）

| type | 说明 | 可执行操作 |
| --- | --- | --- |
| `material` | 材料 | 出售 |
| `food` | 食物 | 食用（回血）、出售、设为自动进食 |
| `pill` | 丹药 | 使用（聚气/疗伤）、出售；`use:'break'` 的丹药仅突破时自动消耗 |
| `equip` | 装备 | 装备、出售 |
| `seed` | 种子 | 用于灵植种植、出售 |

物品字段：`name / icon / value / desc`，食物含 `heal`，丹药含 `use`，装备含 `slot` 与属性，种子通过 `FARM_SEEDS` 关联。

## 4. 基本操作

| 操作 | 函数 | 说明 |
| --- | --- | --- |
| 增加 | `invAdd(id, qty)` | 满格且为新种类时返回 false；同时累加 `stats.gained[id]` |
| 移除 | `invRemove(id, qty)` | 数量归零则删除该键 |
| 查询 | `invCount(id)` / `invHas(id, qty)` | 数量 / 是否足够 |
| 扩容 | `buyInvSlot()` | 扣灵石、`invSlots += 1`、写日志 |
| 出售 | `sellItem(id, qty)` | `qty < 0` 表示全部出售 |

出售价：

```
sellPrice(id) = max(1, floor(value × SELL_RATIO(0.55) × (1 + formBonus('sell')) × (1 + worldBonus('sell'))))
```

- 聚宝阵「出售价」阵纹与洞天茶肆 / 驿馆 / 大市集 / 商行可提升出售收益；市集进货价使用同一行情倍率，因此买卖价差不会被加成放大。

## 5. 界面与交互

### 5.1 背包面板

- 头部下方新增**扩容条**：`📦 当前容量 X 格 · 每次扩容 +2 格 · 下次 💠N` + 「扩容 +2」按钮。
- 灵石不足时按钮置灰；`updateInvQty()` 每次刷新会同步按钮可用状态与容量数字，无需重建面板。
- 按 `ui.invFilter` 筛选：全部 / 材料 / 食物 / 丹药 / 装备 / 种子等。
- 每格显示图标、名称与数量；数量走 `updateInvQty()` 增量刷新（`data-qty` 节点）。
- 容量显示为 `已用种类 / invCap()`（侧栏按钮与面板头部共用 `data-invcount`）。

### 5.2 出售模式（`ui.invSellMode`）

- 开启后，**点击格子仍弹出操作菜单**，只是金色主按钮由「使用」变为「出售 ×N」，数量条标签变为「出售数量」；格子样式变为金色边框以示区分。悬浮提示：普通「点击查看 / 使用」、出售模式「点击查看 / 出售 ×N」。
- 关闭（普通模式）时，主按钮为「使用」（食用 / 服用 / 装备），出售为次要按钮。

### 5.3 操作菜单（popover）

数量条与所有按钮共用同一个 `ui.itemQty`（预设 ×1/×5/×10/×25/×100/全部 + 自定义输入框，1–9999）。
**主操作随模式切换**：普通模式金色主按钮为「使用」，出售模式金色主按钮为「出售」；数量条标签也同步显示「使用数量 / 出售数量」。

| 物品类型 | 菜单项 |
| --- | --- |
| 食物 | 食用 ×N（主）、出售 ×N、全部出售 |
| 丹药（含 break） | 服用 ×N（主；break 丹为「使用」，点击提示需在修炼面板突破时消耗）、出售 ×N、全部出售 |
| 装备 | 装备（主）、出售 ×N、全部出售 |
| 材料 / 种子 | 出售 ×N、全部出售 |

**批量使用**（按钮文案直接反映数量，如「服用 ×25」；持有不足时按实际持有量显示）：

- 修为 / 悟性类丹药：按数量全额生效，一次性结算并合并为一条日志（如「服下「聚气丹」×5，修为 +X」）。
- 疗伤丹 / 食物：**只吃到满血为止**，多余剂量不会被浪费——若一枚即可回满，批量使用不会消耗第二枚。
- 实际消耗枚数由 `usePill(id, qty)` / `eatFood(id, qty)` 返回；`qty = -1` 表示全部。

> 打开弹层时 `handleClick` **提前 return，不重绘整树**，避免弹层被销毁。

### 5.4 事件绑定

| `data-act` | 行为 |
| --- | --- |
| `filter` | 切换筛选 |
| `invslot` | 始终弹出操作菜单（出售模式下主按钮为「出售」） |
| `togglesell` | 切换出售模式 |
| `invup` | 购买一次背包扩容 |
| `sell` / `sellall` | 卖指定数量 / 全部 |
| `eat` / `use` / `equip` / `unequip` | 对应操作 |
| `closepop` | 关闭弹层 |

## 6. 与其他系统的关系

```
采集 / 炼制 / 掉落 ──invAdd──► 背包 ──┬─ 使用(食物/丹药) ─► 回血 / 修为
                                      ├─ 装备 ──────────► 战斗属性
                                      ├─ 种植(种子) ─────► 灵植地块
                                      └─ 出售 ──────────► 灵石 ─► 市集/突破/扩容
```

- **背包满**会阻塞「新增种类」的产出，因此长挂机前应清理或出售冗余物品，或先扩容。
- 签到第 7 天信徒、锁妖塔/裂缝奖励等使用 `invCap()` 判断空位，扩容后自动获得更大的奖励容纳空间。

---

## 7. 存档兼容

- `state.invSlots` 为新增字段：旧档缺失时默认 0，容量保持 100，行为与旧版本完全一致。
- `mergeState` 会做整数化与上下限钳制（`[0, 60]`），异常存档不会出现负容量或超过 220。
- 扩容只改 `state.invSlots` 与 `state.gold`，不触碰 `state.inv` 结构。

---

## 8. 扩展指引

- 新增物品：在 `ITEMS` 追加并指定 `type`；若为新类型，需在筛选与 popover 逻辑中登记。
- 新增容量读取逻辑：必须调用 `invCap()`，不要硬编码 100 或 `CONFIG.INV_SLOTS`。
- 若未来需要「按数量上限」而非「按种类上限」，需改动 `invSlotsUsed` 语义并同步全部调用点。
- 装备/丹药的特殊操作按 `type` 与 `use` 字段分流，新增类型时注意补齐菜单分支。
