# 机制 · 任务系统

> 相关代码：`js/data.js`（`TASKS`）、`js/engine.js`（`taskDone/checkTasks/claimTask/findTask`）、`js/main.js`（`claim` 事件）

任务是**成就式**的引导与奖励系统：达成条件后解锁「可领取」状态，玩家主动领取奖励。

---

## 1. 任务结构

```js
{ id, name, desc, cond: { type, ... }, reward: { gold?, spirit?, items?: [{id, qty}] } }
```

- 进度记录：`state.tasks[id] = { done, claimed }`。
- **达成**（`done`）与**领取**（`claimed`）是两个独立状态。

---

## 2. 条件类型（`cond.type`）

| type | 判定 | 依据 |
| --- | --- | --- |
| `gathered` | 累计采集次数 ≥ n | `state.stats.gathered` |
| `kills` | 累计击杀 ≥ n | `state.stats.kills` |
| `crafts` | 累计炼制（配方）次数 ≥ n | `state.stats.crafts` |
| `pills` | 累计炼出丹药数 ≥ n | `state.stats.pills` |
| `breaks` | 累计突破成功次数 ≥ n | `state.stats.breaks` |
| `level` | 指定技能等级 ≥ lvl | `state.skills[skill].lvl` |
| `realm` | 境界阶数 ≥ stage | `state.skills.cultivation.lvl` |
| `item` | 累计获得某物品 ≥ qty | `state.stats.gained[id]` |

> `stats.gained[id]` 在 `invAdd` 时单调累加，可统计「累计获得」而非「当前持有」。

## 4. 流程

### 4.1 达成检测（`checkTasks`）

- 每秒（`taskTimer`）遍历 `TASKS`；
- 未达成的任务若 `taskDone` 为真 → 置 `done = true`，写一条「可前往任务面板领取奖励」的日志；
- 已达成的任务不重复提示。

### 4.2 领取（`claimTask`）

- 前置：任务存在、`done` 为真、未 `claimed`；
- 置 `claimed = true`；
- 发放 `gold` / `spirit` / `items`；
- `invAdd` 发放物品（背包满时可能失败，需先清理背包）。

---

## 5. UI 表现

- **侧栏「📜 任务」**：显示达成 / 总数进度。
- **任务面板**：任务条目（名称、描述、条件、奖励预览），状态分为：
  - 未达成（置灰）；
  - 已达成待领取（高亮「领取」按钮）；
  - 已领取（标记完成）。
- 领取按钮绑定 `data-act="claim"`。

---

## 6. 扩展指引

新增任务：在 `TASKS` 追加条目即可，`cond` 选取已有类型（或扩展 `taskDone` 增加新判定）。`mergeState` 会为新任务补默认进度记录。
