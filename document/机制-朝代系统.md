# 机制 · 洞天朝代（DYNASTY）

> 版本：v2.5.0 ｜ 配置：`js/data.js` 的 `DYNASTY` / `DYNASTY_ERA_RES` / `BUILDINGS.smallworld`
> 状态：`state.seed`、`state.world.dynasties[]`、`state.world.dynAccum`
> 入口：洞天 → 「🕰️ 朝代」页签

## 1. 定位

洞天第二条人口线：玩家用新资源「生命之种」召唤不同年代的生灵，每个朝代是一个独立人口池，每 10 分钟结算一次，为洞天提供粮食、木材、石料或全局灵石 / 星砂。与既有的「洞天人口」互不影响：原有 `world.pop` 仍由民居与粮食决定，朝代人口是另一套独立的、只能靠合成提升上限的长期池子。

设计目标：把「穿越星球的朝代序列」变成可经营的资产，让中后期的星球/裂缝产出有一个新的消耗口，同时用「上限只能合成」的限制避免一次性堆人口。

## 2. 新资源：生命之种 🌱

存档字段：`state.seed`（整数，旧档缺失按 0）。

| 来源 | 规则 | 量级 |
| --- | --- | --- |
| 穿越星球吸收物品 | 每吸收 1 件独立 roll，**2%** 掉 1 颗 | 稳态约 0.4~0.5 颗/分（按 20~25 件/分） |
| 五行属性裂缝修复 | **50%** 掉 **2** 颗 | 每次 0~2 颗，每 3 小时最多 3 次 |
| 异界裂缝修复 | **必掉** `3 + floor(层/10)` | 0 层 3 颗，10 层 4 颗… |
| 裂缝怪物击败 | **必掉** `5 + floor(强度/5)` | 强度 0 → 5 颗，25 → 10 颗 |

节奏说明：星球是主要来源但概率低（鼓励持续挂机），两类裂缝是「打一场就有一笔」的确定性补充。按每天 1 只裂缝怪物 + 若干次异界裂缝 + 星球挂机估算，日均约 150~250 颗；若 12 小时离线全在运转，另加约 300 颗。生命之种因此是软门槛，真正的硬门槛是朝代位（小世界等级）。

召唤消耗 **10 颗**，合成消耗 **4 颗**。

## 3. 建筑：小世界（秘境）

| 等级 | 造价 | 朝代位 |
| --- | --- | --- |
| Lv.1（首建） | 💠 6000 灵石（不收木/石） | 5 |
| Lv.2 | 💠 9000 · 🌲 400 · ⛰️ 400 | 10 |
| Lv.3 | 上一级 ×1.18 | 15 |
| Lv.n | `costLv1 × 1.18^(n-1)` | `5n` |

- 地形：秘境 `mystic`；建设度门槛 `req = 1`（与引力塔 / 招贤殿同门槛，不额外卡建设度）。
- **境界门槛：第 22 阶 = 元婴期初期**（`realmReq: 22`）。未达标时按钮置灰、卡片角标显示「需元婴期」、`title` 提示「需达到 元婴期」，引擎层 `buildBuilding()` 二次拒绝。
- 首建只收灵石（6000），与「元婴期玩家的灵石量级」匹配：此时洞天高阶建筑单级造价约 3000~6000，6000 是一次明显的目标而非遥不可及。第 2 级起需要木/石（各 400），与建设度 60~90 段建筑的用料量级一致。
- 选择 `costLv1` 而不是把 `cost.wood` 写成 0：`buildCost()` 对 `costLv1` 单独取基准，避免「0 × 1.18^n = 0」导致后续等级永远白嫖材料。

## 4. 朝代与人口

存档结构：

```js
world: {
  dynasties: [ { dyn: 0, pop: 3, cap: 12 } ],  // dyn = 年代下标
  dynAccum: 0                                   // 距下次结算的累计秒
}
```

### 4.1 召唤

- 随机年代，范围 `[0, eraMax]`；`eraMax = clamp(穿越次数, 1, 50)`。0 次穿越只能召到清朝/明朝，每 1 次穿越多解锁 1 个年代，20 次穿越可到「古十纪」。
- 年代名沿用 `planetDynastyName()`：0~10 为清朝…夏朝，11 起为「古一纪 / 古二纪…」。
- 初始 `pop = 3`，`cap = 12`。
- 可重复召唤同一朝代（这正是合成的前提）。

### 4.2 人口增长与上限

- 每 **600 秒（10 分钟）**结算一次：`pop += max(1, pop × 6%)`，封顶 `cap`。
- 上限只能通过**合成同名朝代**提升，不能自然增长。
- 硬顶 `POP_HARD_CAP = 5000`，防止改档 / 数值漂移。
- 3 → 12 需要约 9 次结算（约 90 分钟），与「小世界首建后可感知成长」的节奏匹配。

### 4.3 合成

- 条件：两个**不同位置、同一朝代**、被合者人口 ≥ 2、生命之种 ≥ 4。
- 结果：`目标.pop += 被合者.pop × 50%`；`被合者.pop -= 同量`；`目标.cap += ceil(被合者.cap × 50%)`。
- **被合朝代不会消失、不空出朝代位**：原文「被合成的朝代消耗一半人口，另一半人口并入目标朝代」即此语义。因此合成是一次「把两个池子合并成一个更大的池子」的长期投资，而不是腾位置的手段。
- 被合者人口下限为 1（`MERGE_MIN_POP / 2`），避免出现 0 人口死池。

### 4.4 产出

每次结算，每个朝代产出：

- 🌾 粮食：`pop × 3`（进洞天仓储，受 `worldCap` 限制）
- 主资源：`pop × per`，按年代映射：

| 年代 | 主资源 | 每人口/次 |
| --- | --- | --- |
| 清朝 / 明朝 | 🌲 木材 | 4 |
| 元朝 / 宋朝 | ⛰️ 石料 | 4 |
| 唐朝 / 南北朝 / 两晋 | 💠 灵石 | 0.8 |
| 三国 | ⛰️ 石料 | 5 |
| 周朝 / 商朝 | 💠 灵石 | 1.2 |
| 夏朝 | 🌠 星砂 | 0.15 |
| 古一纪起 | 🌠 星砂 | `min(0.5, 0.15 + 0.02×(n-10))` |

量级校验（5 个朝代 × 人口 12，满编）：

- 若全是清/明：木材 240/10 分 = 24/分，约等于 2 座灵木林；
- 若全是唐/南北朝：灵石 48/10 分 = 4.8/分，约等于 1 级聚宝阁；
- 若全是夏朝：星砂 9/10 分 = 0.9/分，远低于太虚台（12/分）。

即「满编也只是一个中型建筑群的产出」，不会冲击既有经济；但只靠它也能形成稳定被动收入。

## 5. 动作槽与离线

- **召唤 / 合成不占用动作槽**：它们是瞬时消耗型操作，没有持续时间语义；与洞天建筑营造（`buildBuilding`）保持一致。若占用动作槽，玩家会在「召唤 1 个朝代」和「星球运转 / 打裂缝」之间被迫二选一，体验很差，且没有对应的进度条可展示。
- **人口与资源结算为后台被动推进**：挂在 `worldTick` 之后的 `dynastyTick(dt)`，与洞天房屋/灵田的被动产出同一条通道。离线结算 `simulateOffline()` 逐 0.5s 调用 `tick(dt)`，因此朝代结算自动走同一逻辑，受 `CONFIG.OFFLINE_CAP_H = 12` 小时上限约束（最多 72 次结算），不会出现「离线不走」或「离线补刷更多」。
- `dynAccum` 落盘；读档时不重置（保留进度），仅在非法或超出 1 个周期时归零，避免读档瞬间连结算。

## 6. 存档与迁移

| 情况 | 处理 |
| --- | --- |
| 旧档无 `state.seed` | 按 0 |
| `seed` 为负 / NaN / Infinity | 夹到 `[0, 1e12]` 的整数 |
| 旧档无 `world.dynasties` | 空数组（不自动补，避免旧档凭空多出人口） |
| 旧档无 `world.dynAccum` | 0 |
| `dyn.dyn` 非法或超出 `[0, 50]` | 丢弃该条 |
| `dyn.pop` 非有限 | 取初始值 3 |
| `dyn.pop` / `dyn.cap` 超出 `[1, 5000]` | 钳制；`pop > cap` 时压到 `cap` |
| 朝代数量超过 `小世界等级 × 5` | 截断多余条目 |
| `dynAccum` 非法或 ≥ 600 | 归零 |

所有新增字段都有默认值，不破坏 v2.4.0 及更早存档。

## 7. 界面与渲染

- 洞天页签：`🏯 洞天营造` / `🕰️ 朝代 n/N`，切换只改 `state.ui.worldView`，重置合成选中态。
- 朝代页：`data-dyn` 占位 + `updateDynastyState()` 增量写入（种子、倒计时、每张卡的人口/上限/产出/进度条宽度、召唤按钮可用性）。
- 卡片列表只在**召唤**（数量变化）或**进入/退出合成模式**时重建；10 分钟一次的结算不触发 `#content` 或 `.dyncards` 重建（实测同一 DOM 引用）。
- 合成为两段式：点「合成」选中目标 → 同名卡片出现「并入」→ 点击完成。选中面板可取消。

## 10. 设计取舍与风险

1. **不自动补朝代**：旧档第一次进入朝代页是空的，需要自行召唤；避免「上线白拿 5 个朝代人口」。
2. **被合朝代不消失**：严格按需求原文实现，因此合成不会腾出朝代位；玩家需要用小世界等级扩容，而不是靠合成滚雪球。
3. **产出受洞天仓容限制**：粮食/木材/石料会顶到 `worldCap`，此时对应产出被浪费；这与其他洞天建筑一致，玩家需要继续提升建设度扩容。
4. **年代随机不可选**：同一时代只能靠多召唤来凑同名合成，可能短期出现「想要的年代一直不出」的挫败感；当前用「0 次穿越只有 2 个年代」把随机池压小，后期池子变大时靠 5 个位 + 合成消化。
5. **星球掉率是概率项**：离线 12h 的实际种子数有波动（2% 的泊松噪声），但裂缝必掉提供了确定性下限。
