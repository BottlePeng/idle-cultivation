# 机制 · 装备词条

> 版本：v2.22.0 ｜ 对应代码：`js/data.js`（`EQUIP_QUALITY` / `AFFIX_POOL` / `AFFIX_PCT_CAP`）、`js/engine.js`（`rollGearAffixes` / `makeGear` / `grantEquip` / `gearStat` / `affixPct`）、`js/state.js`（实例读档与旧档迁移）、`js/ui.js`（装备卡片 / 穿戴区）

## 1. 目标与存储口径

同名同部位的装备不再是同一件东西：每件装备在**产出时**随机生成 1~N 条词条，词条类型与数值都不同，读档后保持。

- 实例结构：`state.gear = [{ uid, id: itemId, affixes: [{ k, v }] }]`，`uid` 全局唯一。
- 穿戴槽：`state.equip[slot] = uid`（不再是 itemId）。
- 装备**不再进入** `state.inv` 堆叠；每件独立占 1 格，已穿戴不占格。
- 基础模板 `ITEMS[id]` 不改：词条只落在实例上，模板仍用于展示基础属性、售价与图标。

## 2. 品质与条数（按基础 value 分档）

| 品质 | 基础价值 | 词条条数 | 固定值区间（占该装备主属性） | 百分比区间 |
| --- | --- | --- | --- | --- |
| 凡品 | < 300 | 1 | 8%–15% | 1.0%–2.0% |
| 灵品 | 300–999 | 1–2 | 8%–15% | 1.0%–2.5% |
| 玄品 | 1000–2999 | 2 | 9%–16% | 1.5%–3.0% |
| 地品 | 3000–7999 | 2–3 | 10%–17% | 2.0%–3.5% |
| 天品 | 8000–19999 | 3 | 11%–18% | 2.5%–4.5% |
| 仙品 | ≥ 20000 | 3–4 | 12%–20% | 3.0%–5.0% |

- **主属性**指该装备 `max(atk, def, hit, ev)`，最低按 1 计算。
- 生命词条单独按 `(装备生命 || 主属性×4) × 6%~12%` 取整，最低 3。
- 同一件装备同类型词条最多 1 条（重复则重抽）；同名模板的多件实例会尽量避开完全相同的词条组合（最多重试 5 次）。
- 因此凡品武器攻 6 最多出 +1 攻，玄品武器基础攻 16；低阶装备无法靠词条越阶。

## 3. 词条池与权重

| 词条 | 键 | 格式 | 权重 | 实际作用位置 |
| --- | --- | --- | --- | --- |
| 攻击 | `atk` | 固定值 | 20 | `calcStats` 攻击 |
| 防御 | `def` | 固定值 | 17 | `calcStats` 防御（进而影响减伤） |
| 生命 | `hp` | 固定值 | 18 | `calcStats` 生命上限 |
| 命中 | `hit` | 固定值 | 12 | `calcStats` 命中 |
| 闪避 | `ev` | 固定值 | 13 | `calcStats` 闪避 |
| 工作速度 | `speed` | 百分比 | 5 | `speedMul()`（全部动作耗时） |
| 经验获取 | `xp` | 百分比 | 5 | `xpMul()`（含修为） |
| 额外产出 | `double` | 百分比 | 4 | `doubleChance()` |
| 灵力恢复 | `spirit` | 百分比 | 3 | 灵力自然凝聚 |
| 战斗掉落 | `drop` | 百分比 | 3 | 战斗 / 入世掉落率 |

- 百分比词条只加法叠加，**同名全身合计封顶 15%**（`AFFIX_PCT_CAP`），避免 6 件装备把速度/经验叠穿。
- **不设五行词条**：现有五行加成只来自上阵信徒 `elemBonus` 与任务席位，不是玩家可叠的数值通道；硬加会绕过信徒设计。
- **不设战阵词条**：战阵按既有规则不读取玩家装备（见 [战阵](./机制-战阵.md)），词条写进去也不会生效，属于「造不存在的东西」。

## 4. 产出路径：统一 roll

所有装备产出最终都调用 `invAdd(id, qty)`，而 `invAdd` 对 `type === 'equip'` 一律路由到 `grantEquip → makeGear → rollGearAffixes`，因此以下路径**不可能漏 roll**：

1. 炼器锻造（`RECIPES.crafting` 的 `forge`）；
2. 市集装备坊购入；
3. 妖兽 / 章节 Boss / 异界裂缝掉落；
4. 锁妖塔里程碑与宝箱；
5. 任务 / 成就奖励；
6. 七日签到与补发；
7. 洞天朝代首通奖励；
8. 兑换码与测试控制台发放。

容量按「每件占 1 格」计算；背包不足时整批不发放，不会只生成半批。

## 5. 旧档兼容（一次性补 roll）

- 旧档没有 `state.gear`，且 `state.inv` 里可能有装备堆叠、`state.equip` 里是 itemId。
- 读档时一次性迁移：`inv` 中每种装备按数量生成实例，`equip` 中的 itemId 生成实例并把槽位改存 uid；**按当前规则补 roll**。
- 理由：与所有新产出一致；若旧装备「视为无词条」，老玩家会永久少一条词条，且 UI 还要额外处理「空词条」特例。迁移后与新档完全同构。
- 单种装备迁移上限 1000 件，防止异常存档卡死浏览器。
- 读档校验：非法 `id` 整件丢弃；单个词条非法（未知键、非正数、重复键）只丢弃该词条，不丢整件装备；`uid` 重复时自动换新号。

## 6. 操作链

| 操作 | 词条处理 |
| --- | --- |
| 装备 / 卸下 | 同一实例移动，词条完整保留；卸下不复制实例，因此不会刷词条 |
| 替换装备 | 旧装备留在 `state.gear` 中（未穿戴），词条保留 |
| 出售 | 词条随实例一起消失；售价仍按基础 `value` 计算，不做词条溢价（避免经济膨胀） |
| 装备升级 / 熔炼 / 分解 / 作为材料消耗 | **当前游戏没有这些链路**，本次不新增；未来若加，推荐「升级保留词条、熔炼/分解/材料消耗消失、洗练才重 roll」，并另行出文档 |
| 洗练 / 重铸 | **暂不提供**（已确认的边界）：不设入口、按钮或消耗，需要改变词条只能重新获得装备；如后续要做，应作为独立系统并另行出文档 |

## 7. 界面

- **背包**：筛选「装备」或「全部」时，装备以独立卡片展示：品质色名称、部位、基础属性、词条胶囊、与当前同部位装备的属性差（攻/防/命/中/闪），以及「装备 / 出售」按钮。
- **右侧角色卡「装备」区**：显示已穿戴装备的品质、基础属性与词条胶囊；卸下后回到背包卡片列表。
- **市集 / 奖励预览**：仍展示模板基础属性；词条在获得时随机生成，因此不提前展示具体数值。

## 8. 边界与扩展

- 词条只影响玩家面板属性与五条全局产出通道，不参与战阵、不新增货币、不改变市集价格公式。
- 新增词条：在 `AFFIX_POOL` 增加键与权重，并在对应引擎函数接入实际效果；不要在 UI 里写死数值。
- 新增基础属性维度：需同时更新 `calcStats`、`gearStat`、装备卡片与对比键表。
