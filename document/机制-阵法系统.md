# 机制 · 阵法系统

> 相关代码：`js/data.js`（`ACTIONS.formation/FORM_SPECS/FORMATIONS/formCost/formMasteryReq/findFormation`）、`js/engine.js`（`formBonus/formUpgrade/formState/masteryOf`）、`js/main.js`（`formup` 事件）

阵法参考《梅尔沃放置》的**观星 / 星座系统**：通过「观星台」推演天机获得 **星砂**，再以星砂**点亮阵纹**，换取常驻的全局加成。

---

## 1. 两大环节

```
观星（精通等级）──┬──► 💫 星砂 ──► 点亮阵纹 ──► 常驻全局加成
                  └──► 阵纹升级的精通门槛
```

1. **观星**：阵法的采集类动作，产出星砂（**不占背包**，直接计入资源），同时积累该观星的**精通等级**。
2. **点亮阵纹**：消耗星砂提升某条阵纹等级，永久提供百分比加成；**阵纹等级不能超过该观星的精通等级门槛**。

---

## 2. 观星台（`ACTIONS.formation`）

21 门观星，自低到高排列（`ob_qiyao` → `ob_wuxu`），门槛即阵法技能等级要求。

- 星砂产出享受**额外产出翻倍**（`doubleChance`），日志标注「（精通·双倍）」。
- 阵法技能升级需求：`18 × lvl^1.35`（最低的曲线，方便早期铺开阵法）。
- 每门观星都对应**一座**阵法（`FORMATIONS[i].obs` 指向该观星）；观星未解锁 → 对应阵法不可升级。

### 3.1 阵纹通道（`mods[].key`）

阵法只为其他系统提供**加成通道**，本身不消耗。引擎通过 `formBonus(key)` 汇总所有阵法的同类加成：

| key | 作用对象 | 消费方 |
| --- | --- | --- |
| `speed` | 动作周期推进 | `speedMul` |
| `double` | 物品额外产出 | `doubleChance` |
| `mastery` | 精通经验 | `masteryGain` / 战斗精通 |
| `growth` | 灵植生长速度 | `growPlots` |
| `xp_cult` / `xp_gather` / `xp_combat` / `xp_craft` | 各技能经验（按 `XP_GROUP`） | `xpMul` |
| `gold` / `drop` / `sell` | 灵石 / 掉落 / 出售价 | 战斗结算、市集 |
| `hp` / `def` / `regen` | 生命 / 防御 / 脱战回血 | `calcStats`、被动回血 |
| `atk` / `hit` / `ev` | 攻 / 命 / 闪 | `calcStats` |
| `spirit` | 灵力自然凝聚 | `passiveTick` |

## 4. 加成汇总（`formBonus`）

```js
formBonus(key)
  = Σ（遍历所有阵法 × 其阵纹）
    若 m.key === key：加上 min(m.max, 阵纹等级) × m.per
```

- **同类叠加**：多个阵法若有同名 key，加成累加（如七曜阵与灵虚阵都提供 `xp_cult`）。
- 阵纹等级非负、且钳制到 `max`。

---

## 5. 点亮阵纹（`formUpgrade`）

```
cost = floor(基础消耗 × 成长^当前等级 × (1 + 阵纹序号 × 0.35))
精通门槛：formMasteryReq(f, 目标等级) = 目标等级 × 4
```

校验顺序：

1. 阵法存在且 `modIndex` 合法；
2. 阵法技能等级 ≥ 阵法 `req`（等价于「对应观星已解锁」）；
3. 阵纹未满级（< `max`）；
4. **该观星的精通等级 ≥ `4 × (当前等级 + 1)`**（`Lv.1` 需精通 4，`Lv.10` 需精通 40）；
5. 星砂 ≥ `cost`。

通过后：扣星砂、阵纹等级 +1、写入日志。

> **双重门槛**：星砂决定「买得起」，精通决定「练得熟」——想吃满某座阵法的加持，必须先把对应观星刷到精通 Lv.40。

## 6. 与技能经验的联动（`XP_GROUP`）

引擎按技能分组读取阵法经验加成：

| 组 | 技能 |
| --- | --- |
| `cult` | 修炼 |
| `combat` | 战斗 |
| `craft` | 炼器、炼丹 |
| `gather` | 伐木、钓鱼、采矿、**灵植**以及默认其他 |

- **阵法自身不吃任何阵法经验加成**（避免自循环加速）。

## 7. UI 表现

- **侧栏「🧭 阵法」**：等级与经验。
- **顶栏**：解锁观星后显示 💫 星砂（开局不显示，避免冗余）。
- **阵法面板**：
  - 观星台列表（每门观星带精通 Lv.N 与「双倍 +X% · 耗时 -Y%」）。
  - 阵纹卡片，标题标注「观星 · 七曜 对应」，右上角显示该观星**精通 Lv.N**。
  - 每条阵纹行：当前等级 / 每级与当前加成 / `💫 消耗` 按钮（提示框写明「需观星精通 Lv.X」）。
  - 按钮在「未解锁 / 精通不足 / 星砂不足」时置灰，由 `updateFormState()` 增量刷新。

---

## 8. 扩展指引

新增阵法：

1. 在 `FORM_SPECS` 追加条目（`obs` 必须指向一个观星动作），`FORMATIONS` 会自动推导 `id/req/cost`。
2. 若引入新加成通道 `key`，在对应系统（如 `calcStats`、`passiveTick`、`doubleChance`）读取 `formBonus(key)`。
3. `mergeState` 会自动按当前 `FORMATIONS` 裁剪旧存档的阵纹等级（旧版 6 座阵法的数据会被丢弃）。
