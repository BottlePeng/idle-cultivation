# 机制 · 问道指引

> 相关代码：`js/data.js`（`GUIDE_STEPS`）、`js/state.js`（`state.guide`、旧档推断入口）、`js/engine.js`（`guideCurrent/guideStepDone/guideSync/guideFlag/guideInfer/guideSkip/guideClose/guideReopen/guideNudging`）、`js/ui.js`（`renderGuide/updateGuide/applyGuideFocus`）、`js/main.js`（`guidego/guidelist/guideskip/guideclose/guidereopen`）

问道指引是一套**轻量新手教学清单**，与「任务 · 成就」相互独立：

- 任务面板是长期目标（71 条、覆盖到太上境满级）；
- 问道指引只覆盖**开局前 10 个关键动作**，偏教学，步骤更少、奖励更小、完成更快。

它不弹窗轰炸，而是一张常驻右侧的卡片 + 侧栏高亮 + 可随时查阅的清单面板；玩家**实际做出对应行为**才打勾，完成即自动发奖。

---

## 1. 设计目标

- **行为驱动**：不是点「下一步」就算完成，而是读取真实系统状态（技能等级、采集次数、购买、击杀、建设度、阵纹、突破、穿越）。
- **轻量不打断**：右侧卡片常驻但不遮挡操作，只有一块小卡片；侧栏目标入口用金色脉冲提示，不弹模态框。
- **可跳过 / 可关闭**：跳过或收起后不再自动提示；侧栏「📖 问道」仍可随时查看，可手动重新开启。
- **旧档友好**：已有大量进度的存档首次进入时按进度推断已完成步骤（标注「旧档推断」），不会从第一步重新教；推断完成**不补发奖励**，避免一次性资源注入。
- **不通胀**：奖励只有星砂、生命之种、少量丹药，不发灵石。

## 2. 步骤清单（10 步，严格按顺序推进）

| # | id | 标题 | 完成条件（真实行为） | 目标入口 | 奖励 |
| --- | --- | --- | --- | --- | --- |
| 1 | `g_cultivate` | 开始打坐修炼 | 修炼等级 ≥ Lv.2（修为实际增长） | 修炼 | 聚气丹×2 |
| 2 | `g_gather` | 完成 3 次采集 | `stats.gathered` ≥ 3 | 伐木 / 钓鱼 / 采矿 | 星砂 5 |
| 3 | `g_bag` | 打开背包 | 行为标记 `flag:bag` | 背包 | 星砂 5 |
| 4 | `g_shop` | 逛一逛市集 | 行为标记 `flag:shop` | 市集 | 星砂 5 |
| 5 | `g_buy` | 购买第一件物品 | 行为标记 `flag:buy`（`buyItem` 成功后写入） | 市集 | 星砂 10 + 聚气丹×1 |
| 6 | `g_combat` | 击败第一只妖兽 | `stats.kills` ≥ 1 | 战斗 | 星砂 10 + 疗伤丹×2 |
| 7 | `g_world` | 建造第一座洞天建筑 | `worldLevel()` ≥ 5（初始 3 座 1 级建筑 → 建设度 4） | 世界 | 生命之种 1 + 星砂 20 |
| 8 | `g_formation` | 点亮第一道阵纹 | 阵纹等级合计 ≥ 1 | 阵法 | 生命之种 1 + 星砂 20 |
| 9 | `g_break` | 完成第一次突破 | `stats.breaks` ≥ 1 | 修炼 | 星砂 20 + 筑基丹×1 |
| 10 | `g_planet` | 首次穿越星球 | `planet.cross` ≥ 1 | 穿越星球 | 生命之种 2 + 星砂 30 |

奖励合计（新档全做完）：**星砂 125、生命之种 5、聚气丹×3、疗伤丹×2、筑基丹×1**。

设计理由：

- 顺序与核心循环一致：修炼产修为 → 采集产材料 → 背包/市集建立资源流转 → 购买 → 战斗 → 洞天被动产出 → 阵法常驻加成 → 突破 → 穿越开启朝代与稀有产出。
- 选择「修炼 Lv.2」而不是「点击修炼按钮」：进入游戏默认空闲，玩家需主动打开「修炼」并点击「打坐吐纳」；用真实修为增长判定，避免点一下没效果也算完成。
- `worldLevel() ≥ 5`：初始默认送灵田/民居/伐木场各 1 级，建设度为 4；必须**真的建造一次**才会到 5。
- 阵纹与穿越放在后半段，对应玩家第一次接触到星砂与灵气浓度的时点。
- 奖励量级刻意小于任务（任务单条 8~50000 星砂），只够买一两组基础物资/点一道低阶阵纹，不改变经济节奏。

## 3. 推进规则

### 3.1 判定函数

```
guideCurrent()  → 第一个未完成步骤
guideStepDone(step)
  ├─ step.flag → state.guide.flags[flag] === true
  └─ step.cond → condDone(step.cond)        // 与任务系统共用条件实现
guideSync()     → 从当前步骤开始，连续完成所有已满足的步骤
```

- `guideSync()` 每秒随 `taskTimer` 执行一次；`guideFlag()` 在行为发生时立即调用 `guideSync()`，点击后即时打勾。
- **严格顺序**：只允许完成「当前步骤」。如果玩家提前打开了市集（flag 已记录），但当前还停在「打开背包」，则先等背包完成，下一个 tick 会自动补上市集，奖励照发。
- 完成后步骤写入 `state.guide.done[id]`，不会重复发奖。

### 3.2 奖励发放

奖励直接进入 `state.stardust` / `state.seed` / `state.inv`，不经过领取按钮：

```
stardust → state.stardust += n
seed     → state.seed += n
items    → invAdd(id, qty)   // 背包满且为新种类时可能失败
```

日志：`问道指引：完成「…」，奖励已发放。`

### 3.3 行为标记（flag）

| flag | 写入点 |
| --- | --- |
| `bag` | 侧栏点击「背包」或引导「前往」背包 |
| `shop` | 侧栏点击「市集」或引导「前往」市集 |
| `buy` | `buyItem()` 成功扣款后 |

> flag 只记录在 `state.guide.flags`，不参与背包/市集主逻辑，失败购买不会写入。

## 4. 跳过 / 关闭 / 重开

| 操作 | 入口 | 效果 | 持久化 |
| --- | --- | --- | --- |
| 跳过引导 | 右侧卡片「跳过」、清单面板「跳过引导」 | 不再显示卡片，也不再高亮侧栏；进度仍静默记录 | `skipped = true`、`closed = true` |
| 收起提示 | 右侧卡片右上角「×」 | 只隐藏卡片，不改变跳过状态 | `closed = true` |
| 重新显示 | 清单面板「重新开启提示 / 重新显示提示」 | 恢复卡片与高亮 | `skipped = false`、`closed = false` |

- 跳过/收起后**不会自动反复弹出**；只有玩家主动在侧栏「📖 问道」里点「重新开启」才会恢复。
- 跳过不会停止判定：之后玩家做出行为仍会静默完成并发奖，但不打扰。

## 5. 旧存档推断

### 5.1 触发时机

`loadState()` 读取存档时，如果 `saved.guide` 不存在（v2.14.0 之前的所有存档），读档完成后调用 `guideInfer()`。

### 5.2 推断规则

1. 遍历所有 `cond` 型步骤，记录**最靠后的已完成步骤下标** `last`；
2. 若玩家已明显进入中期（修炼 ≥ Lv.15 / 累计采集 ≥ 50 / 击杀 ≥ 10 / 建设度 ≥ 10），则把 `last` 至少推进到第 6 步（战斗），视为教学基础已掌握；
3. 若已有穿越记录（`planet.cross > 0`），`last` 直接设为最后一步；
4. 把下标 ≤ `last` 的步骤全部标记为完成，并写入 `state.guide.inferred[id] = true`；
5. **不发放任何奖励**，避免老玩家一次性获得全部教学资源。

### 5.3 表现

- 清单面板中，推断完成的步骤带「旧档推断」标签；
- 若全部推断完成 → 引导直接收尾，右侧卡片不出现，侧栏显示「已完成 · 可查阅」；
- 若只推断了一部分 → 从第一个未完成步骤继续，而不是从第 1 步开始。

> 例：v2.13.0 的实测存档（已有大量进度、未穿越）被推断为 9/10，当前步骤为「首次穿越星球」，面板前 9 步均带「旧档推断」并显示「已发放」（仅文案，实际未补发资源）。

## 6. UI 约定

### 6.1 右侧常驻卡片（`#guideCard`）

- 位置：右栏顶部、角色卡之前；静态骨架写在 `index.html`，文本由 `updateGuide()` 增量写入 `data-gprog / data-gtitle / data-gdesc / data-ghint`，**不整树重建**。
- 内容：进度 `n / 10`、当前步骤标题、说明、操作提示、按钮「前往 / 清单 / 跳过」、右上角「×」。
- 显示条件：`!skipped && !closed && !finished`；完成/跳过/收起后隐藏。

### 6.2 侧栏入口与高亮

- 侧栏在「签到」下方新增「📖 问道」入口，显示 `n / 10`；完成后显示「已完成 · 可查阅」，跳过显示「已跳过 · n/10」。
- `applyGuideFocus()` 给当前步骤的目标侧栏按钮加 `.guidefocus`（金色边框 + `guidePulse` 光晕脉冲）；若玩家已经在该面板，则不再高亮。
- 高亮只使用 `border` / `box-shadow`，**不使用 transform 位移**，避免撑大滚动区产生横向滚动条。

### 6.3 清单面板（`renderGuide`）

- 顶部状态条：当前步骤提示 / 已完成 / 已跳过 / 已收起；
- 进度条 + `n / 10`；
- 操作区：前往当前步骤、跳过引导、重新开启提示；
- 步骤列表：序号、标题、说明、操作提示、奖励、状态（✅ 已完成 / ▶ 当前 / ○ 未开始）、「旧档推断」标签；
- 底部提示：「后续长期目标请前往任务面板」，明确与任务系统的分工。

## 7. 存档字段

```js
state.guide = {
  done:     { g_cultivate: true, ... },   // 已完成步骤（每个只发一次奖励）
  inferred: { g_bag: true, ... },         // 旧档推断完成（不补奖，仅展示标签）
  flags:    { bag: true, shop: true, buy: true },
  skipped:  false,
  closed:   false
}
```

`mergeState` 校验规则：

- `done` / `inferred` 只保留 `GUIDE_STEPS` 中存在的 id；
- `flags` 只保留配置里出现过的 flag；
- `skipped` / `closed` 仅接受布尔 `true`；
- 旧档无 `guide` 字段 → 默认空记录，读档后走推断；
- `ui.active` 白名单新增 `guide`。

## 8. 与任务系统的分工

| 维度 | 问道指引 | 任务 · 成就 |
| --- | --- | --- |
| 定位 | 开局教学、10 步核心操作 | 全程阶段目标、71 条 |
| 触发 | 实际行为自动打勾 | 条件达成后手动领取 |
| 奖励 | 自动发放、小额 | 手动领取、阶段大额 |
| 结束 | 10 步后收尾，可查阅 | 长期存在 |
| 冲突 | 不重复任务目标；仅覆盖最基础操作 | 不依赖引导，独立判定 |

> 引导不会改变任务进度，也不会替代任务；两者唯一的共享是 `condDone()` 条件实现。

## 9. 扩展指引

- 新增步骤：在 `GUIDE_STEPS` 追加 `{ id, tab, title, desc, hint, cond|flag, reward }`；`tab` 必须与侧栏 `data-skill` 或已有面板 id 一致。
- 新条件类型：直接复用 `condDone`；若需要新的状态读取，先在 `engine.condDone` 增加分支。
- 新行为标记：在对应动作函数里调用 `guideFlag('xxx')`，并在步骤中写 `flag: 'xxx'`。
- 新增步骤会追加到末尾，不会打乱旧档已完成状态（按 id 记录）。
