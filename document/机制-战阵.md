# 机制 · 战阵（信徒战斗）

> 版本：v2.16.0 ｜ 对应代码：`js/data.js`（`DBATTLE` / `DISCIPLE`）、`js/state.js`（`state.dbattle`）、`js/engine.js`（战阵引擎）、`js/ui.js`（战阵面板）、`js/main.js`（入口事件）
>
> 一句话：把仓库里的信徒编成 10 人战阵，自动挑战 60 关妖兽；首通给独特奖励，重复挑战只给少量灵石与账号级「战修经验」。

## 1. 设计目标与已拍板口径

| # | 口径 | 本实现 |
| --- | --- | --- |
| 1 | 10 个位置，5 个职业专位 + 5 个通用位 | 前排 0~4 通用；后排 5~9 专位，依次只收皇帝 / 皇后 / 丞相 / 将军 / 皇妃，每位限 1 人 |
| 2 | 战阵独立，身份互斥 | 不占 12 个任务席位、不占朝代 8 个职位；同一信徒只能是「任务 / 职位 / 战阵」之一 |
| 3 | 不做第二座金币塔 | 首通给星砂 / 生命之种 / 世界资源 / 章节装备；重复只给 35% 灵石 + 战修经验，**不产**星砂、生命之种、洞天资源、玩家战斗经验与精通 |
| 4 | 不新增货币 | 成长线为账号级「战修等级」，复用现有灵石 / 星砂 / 生命之种 / 粮食 / 木材 / 石料 |
| 5 | 离线不战斗 | 与锁妖塔 / 裂缝一致：读档清空进行中的战阵动作，离线模拟不推进战阵 |
| 6 | 章节 Boss 只掉中档装备 | 最高只到玄铁 / 疾风 / 紫檀档，绝不出混沌、天穹、昆仑等终局装备 |
| 7 | 沿用现有战斗公式 | 命中 `acc/(acc+ev)` 钳 20%~95%、伤害 ±18%、减伤 `def/(def+140)` 上限 75%、敌方减伤上限 30%；**不**复用玩家 `calcStats()` 的装备 / 阵法 / 洞天加成 |

## 2. 战阵编成

### 2.1 位置结构

| 索引 | 位置类型 | 可上阵职业 | 说明 |
| --- | --- | --- | --- |
| 0~4 | 通用位（前排） | 任意 | 敌方 70% 概率优先攻击前排 |
| 5 | 皇帝专位 | 皇帝 `emperor` | 只收职业为皇帝的信徒，限 1 人 |
| 6 | 皇后专位 | 皇后 `empress` | 只收职业为皇后的信徒，限 1 人 |
| 7 | 丞相专位 | 丞相 `chancellor` | 只收职业为丞相的信徒，限 1 人 |
| 8 | 将军专位 | 将军 `general` | 只收职业为将军的信徒，限 1 人 |
| 9 | 皇妃专位 | 皇妃 `consort` | 只收职业为皇妃的信徒，限 1 人 |

- 每个位置最多 1 人，同一信徒不能重复上阵。
- 专位空缺**不阻止**开战：职业随机，强行要求 5 个专位齐人会因 RNG 卡关。专位只是「更优解」，不是门槛。
- 战阵位数量由招贤殿等级决定：`min(10, 招贤殿等级 × 2)`，即 Lv.1 / 2 / 3 / 4 / 5 分别解锁 2 / 4 / 6 / 8 / 10 位。

### 2.2 身份互斥

一位信徒同一时间只能有一种身份：

1. 已在战阵 → 不能驻守任务、不能担任朝代职位。
2. 已驻守任务 / 已任职位 → 不能进入战阵（下拉候选直接过滤）。
3. 遣散信徒时自动从战阵撤下。
4. 任务 / 职位系统原有的互斥检查保持不变，战阵作为第三种身份接入同一套校验。

### 2.3 关卡门槛

关卡按「章节」要求招贤殿等级，而不是要求专位填满：

```
requiredHall(stage) = min(5, ceil(stage / 10))
requiredSlots(stage) = requiredHall × 2
```

| 关卡 | 招贤殿 | 战阵位 |
| --- | --- | --- |
| 1~10 | Lv.1 | 2 |
| 11~20 | Lv.2 | 4 |
| 21~30 | Lv.3 | 6 |
| 31~40 | Lv.4 | 8 |
| 41~60 | Lv.5 | 10 |

这样每一章对应一次招贤殿升级，解锁节奏与招募 / 仓库扩张同步。

## 3. 仓库容量方案（现实约束与取舍）

### 3.1 冲突

原曲线：`容量 = 2 + (招贤殿等级 − 1) × 3`。Lv.5 只有 14 格，而「10 战阵 + 5 任务 + 8 职位」= 23 位，直接卡死。

### 3.2 方案：抬高容量曲线

| 参数 | 旧值 | 新值 |
| --- | --- | --- |
| `DISCIPLE.BASE_STORE` | 2 | **8** |
| `DISCIPLE.STORE_PER_LVL` | 3 | **6** |

新容量 = `8 + (等级 − 1) × 6`：

| 招贤殿 | 容量 | 可覆盖的编制 |
| --- | --- | --- |
| Lv.1 | 8 | 2 战阵 + 1 任务 + 少量职位 |
| Lv.2 | 14 | 4 战阵 + 2 任务 + 8 职位（14） |
| Lv.3 | 20 | 6 战阵 + 3 任务 + 8 职位（17） |
| Lv.4 | 26 | 8 战阵 + 4 任务 + 8 职位（20） |
| Lv.5 | 32 | **10 战阵 + 5 任务 + 8 职位（23）**，余 9 格 |

### 3.3 为什么选「抬曲线」而不是「砍上阵数」

- 砍上阵数会直接违背 10 位编成的核心体验；分段解锁已经承担了节奏控制，再砍上限等于同一件事做两遍。
- 抬高容量**不改变招募价格**：招募费按历史招募峰值 `1.12^n` 计算，容量只决定「能不能再招」，不会让玩家更便宜地刷信徒。
- 信徒的收益只作用于任务速度 / 经验 / 掉落与朝代职位，不进战斗数值（战阵另有独立面板），扩容不会造成经济通胀。
- 旧档立即受益：容量是派生值，读档后自动按新公式计算，无需迁移字段。

### 3.4 长期取舍（明确写入文档）

- 单朝代满编（23 人）在 Lv.5 有 9 格余量，足够轮换。
- 第二座朝代开始，每朝多 8 个职位；两朝满编 = 31 人，Lv.5 仅余 1 格，必须继续升级招贤殿（每级 +6）才能扩编。这是有意保留的长期资源 sink，而不是 bug。
- 殿堂等级本身受洞天建设度与造价限制，不会让玩家一步到位。

## 4. 信徒战斗属性

### 4.1 品阶基础值

| 品阶 | 生命 | 攻击 | 防御 | 命中 | 闪避 | 出手间隔 |
| --- | --- | --- | --- | --- | --- | --- |
| 凡品 | 70 | 7 | 2 | 10 | 6 | 2.8s |
| 灵品 | 105 | 10 | 3 | 13 | 8 | 2.7s |
| 仙品 | 150 | 14 | 5 | 17 | 11 | 2.6s |
| 神品 | 210 | 19 | 7 | 21 | 14 | 2.5s |

### 4.2 最终属性

```
力量系数 = (1 + 4 × 信徒副属性 power) × (1 + 0.02 × (战修等级 − 1))
生命 = round(基础生命 × 力量系数 × 职业光环生命乘数)
攻击 = 基础攻击 × 力量系数 × 职业光环攻击乘数
防御 = round(基础防御 × 力量系数 × 职业光环防御乘数)
命中 = 基础命中 × 职业光环命中乘数
闪避 = 基础闪避 × 职业光环闪避乘数
```

- `power` 为信徒现有副属性强度（凡 0.020 / 灵 0.030 / 仙 0.045 / 神 0.065，±20% 浮动），因此 `1+4×power` 约为 1.08~1.26。
- 战修等级 1~30，每级 +2%，账号共享；换信徒、换阵容都不丢进度。
- **不使用**玩家装备、阵法、洞天、境界加成，也不读 `calcStats()`。

### 4.3 职业团队光环

| 职业 | 光环 | 每层 | 叠加上限 |
| --- | --- | --- | --- |
| 皇帝 | 全队伤害 | +5% | 2 层 |
| 皇后 | 治疗量 | +12% | 2 层 |
| 丞相 | 技能伤害 | +8% | 2 层 |
| 将军 | 全队攻击 | +10% | 2 层 |
| 皇妃 | 全队生命 | +8% | 2 层 |
| 大统帅 | 全队防御 | +8% | 2 层 |
| 右统帅 | 全队命中 | +8% | 2 层 |
| 左统帅 | 全队闪避 | +8% | 2 层 |

同职业最多计 2 层，避免堆叠同一职业滚雪球；通用位可以放任意职业来补光环。

## 5. 敌方与战斗流程

### 5.1 敌方属性（第 s 关）

```
c = floor((s − 1) / 10)          // 章节 0~5
boss = (s % 10 === 0)

生命 = round(45 × 1.075^(s−1) × (1 + 0.12c) × (boss ? 1.45 : 1))
攻击 = (3 + 0.18(s−1)) × (1 + 0.08c) × (boss ? 1.25 : 1)   // 实际伤害再 ±15%
命中 = 8 + 0.5(s−1)
闪避 = 4 + 0.4(s−1)
减伤 = min(30%, 2% + 0.3%(s−1))
出手间隔 = max(2.0, 3.0 − 0.008(s−1))
```

- 敌方减伤严格沿用 30% 上限。
- 战斗超过 60 秒后进入狂暴：伤害每秒 +3%，最多 ×2，逼迫玩家提升 DPS，而不是靠回血磨死。
- 每 10 关为章节 Boss：生命 ×1.45、攻击 ×1.25，每第 4 次行动追加一次全体 0.8× 攻击。

### 5.2 出手与目标

- 10 位信徒各自按自己的出手间隔独立攻击，不共享回合。
- 敌方每次行动随机选择一名存活信徒：前排（索引 0~4）总权重 70%，后排（索引 5~9）总权重 30%；前排全灭后只打后排。主属性为土的信徒权重 ×2.5（嘲讽倾向）。
- 信徒攻击：`命中率 = hit/(hit+敌闪避)` 钳 20%~95%；伤害 = `攻击 × 0.85~1.15 × (1 − 敌减伤)`。
- 敌方攻击：`命中率 = 敌命中/(敌命中+信徒闪避)`；伤害 = `敌攻击 × 0.85~1.15 × (1 − 防御/(防御+140))`，防御减伤上限 75%。

### 5.3 五行技能（冷却 9 秒，首次随机 5~9 秒）

| 主属性 | 技能 | 效果 |
| --- | --- | --- |
| 金 | 破锋 | 1.6× 攻击单体，无视目标 20% 减伤 |
| 木 | 回春 | 治疗当前生命比例最低的队友：1.0× 攻击 + 8% 目标最大生命（吃皇后光环） |
| 水 | 寒潮 | 0.7× 攻击，并使敌方攻击 −15%，持续 4 秒 |
| 火 | 焚身 | 1.0× 攻击，附加 4 秒灼烧，每秒 0.25× 攻击（吃丞相光环） |
| 土 | 厚土 | 自身获得 18% 最大生命护盾，持续 6 秒，期间防御 +25% |

技能伤害吃丞相光环，治疗吃皇后光环，普攻与技能都吃皇帝 / 将军光环。

### 5.4 胜负

- 敌方生命 ≤ 0：胜利，立即结算；`autoNext` 开启时自动进入下一关（不释放动作槽）。
- 生命跨关卡延续（v2.21.0）：通关、失败、自动连战、扫荡以外的重复挑战都**不再回满**，剩余比例写入信徒实例 `inst.hpPct`；停止 / 切动作 / 读档后继续沿用。只有疗伤能回满。
- 全部信徒倒下：失败，不扣资源、不掉关，释放动作槽；倒下的信徒重伤，需疗伤后才能再战。
- 单个信徒生命归零：立即重伤、自动下阵（槽位清空，不留幽灵队员）；场上无存活单位时按上面的失败流程判负。重伤的锁定与疗伤见 [战阵重伤与疗伤](./机制-战阵重伤与疗伤.md)。
- 自动连战：通关后若任一在场信徒低于 25% 生命，暂停连战并提示；手动挑战不受限制。
- 战斗为纯实时推进，所有计时走 `dbattleTick(dt)`，与 `tick(dt)` 同一时间轴。

## 6. 关卡、章节与奖励

### 6.1 首通 vs 重复

| 奖励 | 首通 | 重复 |
| --- | --- | --- |
| 灵石 | `round(15 × s^1.15)`，Boss ×2 | 首通的 35% |
| 星砂 | `1 + floor(s/5)` | 无 |
| 生命之种 | `1 + floor(s/20)` | 无 |
| 粮食 / 木材 / 石料 | `10s / 12s / 12s`（入库按洞天上限截断） | 无 |
| 战修经验 | `10s` | `10s` |
| 章节 Boss 丹药 + 中档装备 | 仅首通 | 无 |
| 玩家战斗经验 / 精通 | 无 | 无 |

**重复挑战不产星砂、生命之种、洞天资源、玩家战斗经验与精通**，因此不存在「第二座金币塔」。

### 6.2 章节 Boss 掉落（只给中档）

| 关卡 | 丹药 | 装备 |
| --- | --- | --- |
| 10 | 筑基丹 | 玄铁剑 `w_xuan` |
| 20 | 凝元丹 | 玄铁甲 `a_xuan` |
| 30 | 化婴丹 | 玄铁冠 `h_xuan` |
| 40 | 妖元丹 | 疾风靴 `b_fly` |
| 50 | 龙须丹 | 玄铁戒 `r_xuan` |
| 60 | 血玉丹 | 紫檀剑 `w_zi` |

最高只到紫檀档，**不掉**混沌戒、天穹甲、昆仑冠等终局装备。若首通或妖王掉落时背包已满，物品寄存到 `dbattle.pending`，面板显示「待入库 N」，腾出格位后自动入库并写日志，不会丢失。

### 6.3 每日妖王

- 每个本地日期限 1 次，胜利后当日不可再挑战；失败可重试（不消耗次数）。
- 以当前关卡为基准，Boss 模板；奖励：粮食 `250 × 章节`、木材 / 石料各 `300 × 章节`、2 生命之种、5 星砂、1 颗当前章节丹药，**不给灵石**。
- 解锁条件：最高已通关 ≥ 10（完成第一章）。

### 6.4 扫荡

- 仅对「已通关的最高关卡」生效，每天 3 次（按本地日期重置）。
- 立即结算，不占用动作槽、不播放战斗。
- 只给 35% 灵石 + 全额战修经验，不给首通物品、星砂、生命之种、世界资源。

## 7. 战修等级（账号级成长线）

- 范围 1~30 级，账号共享，不随信徒变化。
- 每级：战阵内信徒生命 / 攻击 / 防御 +2%（乘算）。
- 升级需求：`round(50 × 当前等级^1.4)`；经验来源为所有战阵胜利（首通、重复、每日妖王、扫荡都算）。
- 满级后经验不再累积，面板显示「战修圆满」。
- 战修等级**不进入**玩家 `calcStats()`，只影响战阵单位。

## 8. 动作槽与存档

### 8.1 动作槽

- 新增动作 `{ skill: 'dbattle', id: 'stage' | 'daily' }`。
- `cycleTick` 显式跳过 `dbattle`，避免被判为无效动作清空。
- 开始战阵前调用 `planetInterrupt()` / `cancelCombat()`；任何其它动作开始 / `stopAction()` 都会调用 `dbattleStop()`，防止后台残留。
- `combatTick` 不感知战阵；战阵由独立的 `dbattleTick(dt)` 驱动，在主循环 `tick(dt)` 中调用。
- 离线模拟：`dbattleTick` 在 `OFFLINE_MODE` 下直接返回；读档时不恢复 `dbattle` 动作。

### 8.2 存档结构

```js
state.dbattle = {
  stage: 1,          // 当前关卡（1~60）
  best: 0,           // 最高已通关关卡（0 = 尚未通关）
  lineup: [null × 10], // 索引 0~4 通用，5~9 专位
  cleared: {},       // { [stage]: true } 首通记录
  trainLvl: 1,       // 战修等级 1~30
  trainXp: 0,        // 当前等级战修经验
  autoNext: true,    // 胜利后自动下一关
  dayKey: '',        // 每日妖王 / 扫荡所属日期 'YYYY-MM-DD'
  dailyBoss: false,  // 今日妖王是否已胜
  sweeps: 0,         // 今日已扫荡次数
  pending: [],       // 背包满时寄存的丹药 / 装备，腾出格位后自动入库
  stats: { wins: 0, losses: 0 }
};
```

瞬态（不落盘）：`DB.units`、`DB.enemy`、`DB.log`、`DB.phase`、`DB.timer`、`DB.mode`、`DB.stage`。

重伤与残血不放在 `dbattle` 里：标记存在信徒实例 `inst.injured = true` / `inst.hpPct`（0~1，缺失 = 满血），跟着信徒走；遣散 / 化道消耗时实例消失，标记自然清除。详见 [战阵重伤与疗伤](./机制-战阵重伤与疗伤.md)。

### 8.3 读档校验

1. `lineup` 归一为长度 10 的数组。
2. 丢弃不存在的 uid、重复 uid、已驻守任务 / 已任职位 / 已遣散 / 重伤未愈的 uid。
3. 专位（5~9）上职业不匹配的 uid 一律清空。
4. 超出当前解锁位数的槽位清空。
5. 清空进行中的 `dbattle` 动作；`stage` 夹到 1~60，`best` 夹到 0~60，`trainLvl` 夹到 1~30。
6. `dayKey` 不是今天的，重置 `dailyBoss=false`、`sweeps=0`。
7. 清空 `state.dbattle` 的运行时字段（若有旧档误存）。

## 9. 与现有系统的边界

| 系统 | 关系 |
| --- | --- |
| 任务席位 | 不变，仍为招贤殿等级；战阵不占任务位 |
| 朝代职位 | 不变，仍为 8 个；战阵不占职位，专位职业只借用职业枚举 |
| 仓库容量 | 改为 `8 + 6 × (等级−1)`，见第 3 节 |
| 锁妖塔 / 裂缝 | 共用一个动作槽，互斥；均不产离线收益 |
| 玩家战斗 | 战阵不产玩家战斗经验 / 精通，不读玩家装备 / 阵法 / 洞天 |
| 市集 | **完全未改动**（价格、买卖、套利逻辑保持原样） |
| 重伤 / 疗伤 | 生命归零自动下阵并进入重伤；战阵生命跨关延续、通关不回血；只能灵力 + 1 枚聚气丹恢复，无自然自愈；与玩家自身疗伤完全分离，详见 [战阵重伤与疗伤](./机制-战阵重伤与疗伤.md) |
| 世界资源 | 首通与每日妖王给粮食 / 木材 / 石料，按现有 `worldCap` 截断 |

## 10. 体验预期

- **Lv.1 招贤殿**：2 人战阵，第 1 关约 12 秒，第 10 关 Boss 约 30~35 秒；靠升级殿堂扩位。
- **Lv.3**：6 人战阵，第 25 关约 20 秒。
- **Lv.5 满编**：10 人战阵，第 50 关约 70 秒，第 60 关约 85~90 秒；战修等级与品阶决定能否压过 60 秒狂暴线。
- 专位齐全 + 职业光环合理的阵容，推进速度约比通用位堆叠快 15%~25%，但不构成硬门槛。
