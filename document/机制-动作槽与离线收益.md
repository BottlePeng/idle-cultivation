# 机制 · 动作槽与离线收益

> 相关代码：`js/engine.js`（`tick/cycleTick/startAction/stopAction/simulateOffline`）、`js/main.js`（`startLoop`）、`js/state.js`（`state.action`）

---

## 1. 设计目的

- **单一动作槽**是全局的核心约束：任意时刻只允许一件事在进行，让玩家的选择具备取舍成本，避免「全自动多线程」导致的数值通胀。
- **离线收益与在线一致**：离线不是另写一套公式，而是用同一个 `tick` 快进模拟，保证玩家在线 / 离线得到完全相同的产出。

---

## 2. 动作槽模型

```js
state.action = { skill, id }   // 当前动作；null 表示空闲
state.actionTimer = 0          // 当前周期已累计秒数
state.actionWaiting = false    // 是否因缺材料/背包满而原地等待
```

占用动作槽的对象：

| 类别 | 说明 | 入口 |
| --- | --- | --- |
| 采集 / 观星 / 打坐 | `ACTIONS` 中的无消耗动作 | `startAction(skillId, actionId)` |
| 配方 | `RECIPES` 中的有消耗配方 | `startAction(skillId, actionId)`（对炼器/炼丹面板） |
| 战斗 | 循环讨伐某妖兽 | `startCombat(monsterId)` |
| 种植 / 收获（灵植） | `plantSeed` / `harvestPlot` 为即点即结算的短暂操作 | 见 [灵植系统](./机制-灵植系统.md) |

> **不占槽的被动过程**：灵力自然凝聚、脱战回血、**灵植生长**等放在 `passiveTick(dt)`，与动作槽并行推进。

### 2.1 切换与开关语义

- 点击**同一动作**（同 skill 同 id）→ 视为 **停止**（toggle 语义）。
- 点击**不同动作** → 直接切换，`actionTimer` 归零。
- 点击战斗妖兽同上：再次点击同一目标即停止。

### 2.2 缺材料 / 背包满

`cycleTick` 在每次推进前检查：

- **缺材料**（配方 `in` 不足）或 **背包已满**（产出无法放入）→ `actionTimer` 停在 `t`，标记 `actionWaiting = true`，**原地等待不中断**，并只提示一次。
- 条件恢复后自动继续，记录一条「继续运转」日志。

> 设计意图：挂机不该因为一次材料耗尽就静默中断。

## 3. 周期推进（`cycleTick`）

```
t = effTime(def, id)                        // 精通会缩短耗时
state.actionTimer += dt * speedMul()        // 受大境界 + 疾风阵加速
while (actionTimer >= t) {                  // 支持一帧补多次（离线用）
  actionTimer -= t
  keep = completeActivity(act, def)
  if (!keep) stopAction(true)               // 材料不足等 → 中止
}
```

- `speedMul() = (1 + 大境界数×0.04) × (1 + formBonus('speed'))`
- `effTime(def,id) = def.time × (1 − min(0.20, 精通Lv × 0.002))`
- 单次推进保护上限 200 次循环，避免异常卡死。

### 3.1 一次动作完成（`completeActivity`）

**配方类**（`def.in` 非空）：扣材料 → 结算产出（灵力/灵石/回复/修为/物品）→ `stats.crafts++` → 加技能经验 + 精通。

**采集 / 观星 / 打坐类**：

- 产出物品：按 `doubleChance(id, skillId)` 概率翻倍（标记「精通·双倍」）。
- 观星产出星砂：同样享受额外产出翻倍。
- 炼丹采药：额外 30% 概率掉落对应种子（详见灵植文档）。
- 结算 `spirit/gold/heal`，加技能经验 + 精通。

## 4. 离线收益（`simulateOffline`）

### 4.1 触发

`boot()` → `loadState()` 返回离线秒数（`Date.now() − state.lastSave`）；若 > 3 秒则结算。

```js
report = simulateOffline(offlineSeconds)
```

### 4.2 结算算法

```
capped = min(seconds, OFFLINE_CAP_H * 3600)   // 上限 12 小时
STEP   = 0.5 秒
OFLINE_MODE = true           // 静默：logMsg 不写日志，动画类日志被抑制
while (remain > 0) { tick(min(STEP, remain)); remain -= STEP }
guard < 400000               // 循环保护
```

- 因为**复用同一 `tick`**，离线同样推进：动作循环、战斗、被动回血、灵力凝聚、**灵植生长**、任务判定。
- 结束对比 `snapshotOffline()` 的前后快照，汇总收益报告。

### 4.3 报告内容（`renderOfflineReport`）

| 项 | 说明 |
| --- | --- |
| 离线时长 | 分钟 / 小时显示；超出上限则标注「按上限 12 小时结算」 |
| 资源 | 灵石、灵力、星砂增减 |
| 战斗 | 击杀数、死亡数 |
| 收获 | 背包中净增的物品（最多列 12 种） |
| 升级 | 各技能 / 境界的等级提升 `from → to` |

### 4.4 离线期间不会发生的事

- 不写 `state.log`（`OFFLINE_MODE` 抑制），避免刷屏；仅以报告呈现。
- 无双倍产出的动画区分，但概率判定照常生效。
- 任务进度照常累计（`checkTasks` 每秒执行）。

## 5. UI 表现

- **底部当前动作条**：动作名 + 进度条 + 「停止」按钮；空闲时显示提示文案。
- **侧栏技能按钮**：正在进行的技能显示进度条与 `dot` 强调点。
- **战斗面板**：显示「搜寻 / 讨伐」状态。

进度条渲染走 `updateBars()` 增量刷新（`data-bar` 占位节点），不随面板重绘。

---

## 6. 边界与保护

| 场景 | 处理 |
| --- | --- |
| 标签页被挂起 | `tick` 中 `dt > 2` 时截断为 2 秒 |
| 切走 / 关闭页面 | `visibilitychange` 与 `beforeunload` 触发 `saveState` |
| 离线时长 > 12h | 按 12h 结算并标注 |
| 旧存档引用了已删除的动作 | `mergeState` 校验 `findActivity`，否则回落默认 `cultivation/meditate` |
