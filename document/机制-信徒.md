# 机制 · 信徒（五行齐全 · 主属性）

> v2.9.2 起，每位信徒五行齐全（金木水火土），并随机拥有 1 个「主属性」；
> 每个主动任务都能上阵 1 位信徒：主属性命中吃高加成，副属性命中吃基础加成。
> v2.9.5 起，信徒还可担任洞天朝代的 8 个永久职位（皇帝、皇后、丞相、将军、皇妃、大统帅、右统帅、左统帅，见第 4.1 节）。

## 1. 解锁与容量

信徒系统由**洞天建筑「🏛️ 招贤殿」**解锁（秘境地形，门槛建设度 1，**开局即可营造**）。

首次营造只需 **700 灵石**（req ≤ 1 的建筑首建免木材/石料，从 Lv.2 起才需要材料）。

```
容量（含上阵） = 2 + 3 × (招贤殿等级 − 1)
上阵位数        = 招贤殿等级 × 1（未建造时为 0，信徒只能待在仓库）
```

| 招贤殿等级 | 容量 | 上阵位 | 可招最高品阶 |
| --- | --- | --- | --- |
| 未建造 | 0 | 0 | — |
| Lv.1 | 2 | 1 | 凡品 |
| Lv.2–3 | 5–8 | 2–3 | 灵品 |
| Lv.4–7 | 11–20 | 4–7 | 仙品 |
| Lv.8+ | 23+ | 8+ | 神品 |

容量是**总数**（仓库 + 上阵）；上阵不额外占容量，上阵位单独由招贤殿等级决定。
**上阵总数仍受招贤殿限制**：12 个任务各有 1 个席位，但同时最多只能上阵「招贤殿等级」位。

## 3. 信徒五行与品质

每位信徒是一个**实例**，五行固定齐全，主属性与强度在招募时随机：

```js
{ uid, id, tier, elems: ['metal','wood','water','fire','earth'], main: 'water', power: 0.065 }
```

- `elems`：固定为金、木、水、火、土五行齐全；
- `main`：从五行中随机抽取 1 种作为主属性；
- `power`：**副属性强度**，品质基准 ×(1 ± 20%)，保留三位小数；
- 主属性强度 = `power × MAIN_MULT[tier]`，由 `discMainPower(tier, power)` 计算。

| 品质 | 副属性基准 | 副属性区间 | 主属性倍率 | 主属性基准 | 主属性区间 | v2.9.1 单条（对照） | 招募权重 | 招贤殿解锁 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 凡品 | 2.0% | 1.6% ~ 2.4% | ×2.0 | 4.0% | 3.2% ~ 4.8% | 4%（3.2% ~ 4.8%） | 55 | Lv.1 |
| 灵品 | 3.0% | 2.4% ~ 3.6% | ×2.2 | 6.6% | 5.28% ~ 7.92% | 6%（4.8% ~ 7.2%） | 30 | Lv.2 |
| 仙品 | 4.5% | 3.6% ~ 5.4% | ×2.3 | 10.35% | 8.28% ~ 12.42% | 9%（7.2% ~ 10.8%） | 12 | Lv.4 |
| 神品 | 6.5% | 5.2% ~ 7.8% | ×2.4 | 15.6% | 12.48% ~ 18.72% | 13%（10.4% ~ 15.6%） | 3 | Lv.8 |

与 v2.9.1 的对照结论：

- 按单个任务看：主属性 ≈ 旧单条的 **100% ~ 120%**，副属性 = 旧单条的 **50%**。
- 若随机挑一个任务，期望约为旧版的 **60% ~ 64%**（0.2 × 主属性 + 0.8 × 副属性），整体不升反降；只有主属性命中的那一个任务略高，加成不会失控。
- 四种副属性**等值**（共用同一个 `power`）：规则最直观、面板最好读，也避免玩家为了 0.1% 的浮动反复重掷。

## 4. 上阵规则

- 每个主动任务 1 个信徒席位；因为五行齐全，**任何任务都能上阵**，区别只在主属性 / 副属性命中。
- 一位信徒**只能同时挂一个任务**；改挂到别处会自动从原任务撤下。
- 上阵总数 ≤ 招贤殿等级；已满时新的任务席位不可再选，需先撤下或升级招贤殿。
- 招募费：`floor(600 × 1.12^历史招募峰值)`；峰值只增不减，遣散信徒不会让费用回落。品阶权重只在当前招贤殿可招池内归一。

### 4.1 与朝代职位的互斥（v2.9.5）

- 信徒可以担任洞天朝代的 8 个职位（皇帝、皇后、丞相、将军、皇妃、大统帅、右统帅、左统帅），为整朝产出（粮食 + 年代主资源）提供 +5% ~ +24% 的永久加成；神品满编合计 +85%（数值见《机制-朝代系统》4.5）。
- **一位信徒全局只能有一个身份**：任务驻守或朝代职位二选一。
  - 已任职位者不出现在任务上阵下拉里，`assignDisciple()` 会二次拒绝并提示「正在担任 X 丞相，不可驻守任务」；
  - 已驻守任务者不出现在朝代职位候选里，因为候选只取「未驻守任务且未任其它职位」的信徒。
- **朝代职位不占用招贤殿上阵位**：`discipleEquippedCount()` 只统计 `state.disciples.assign`，职位另存于 `state.world.dynasties[i].posts`（8 个键的通用映射）。这样永久任命不会不可逆地挤掉任务席位。
- 职位上任后不可取下、不可更换；只有两种解除方式：遣散该信徒，或该朝代被合成消失。**v2.9.4 起，合成消失时所有在任职位会随朝代一起永久销毁**（从 `owned` 移除），不再回到信徒仓库；合成确认框会逐名提示，且追加第二次确认。

## 5. 遣散（删除信徒）

- 仓库卡片右下角有「遣散」按钮，点击后弹出**二次确认**；确认文案包含品质、五行（齐全）、主属性与副属性强度、当前驻守任务 / 当前朝代职位（如有）以及「删除后不可恢复」。
- 若该信徒正在驻守某个任务，**自动撤下再删除**（不禁止删除）。理由：遣散本身是玩家明确发起的破坏性操作，确认框已写明会撤下；自动清理能保证 `assign` 永远不残留悬空 uid，也避免「必须先撤下再删」的额外往返。
- 若该信徒正在担任朝代职位，同样**先清空职位引用再删除**：确认文案显示「当前职位：清朝丞相（删除后该职位将空缺，不可恢复）」，删除后该朝代对应职位变为空缺。这与「上阵信徒删除自动撤下」保持一致，`state.world.dynasties[i].posts` 中不会留下悬空 uid。
- 另有一条被动销毁路径：所在朝代被合成时，所有在任职位会随朝代一起永久销毁（v2.9.4），详见《机制-朝代系统》4.3 / 4.5。销毁同样会清理 `assign` 与职位引用，且不退还招募费、不改变 `peak`。
- 删除只影响 `owned`、`assign` 与朝代职位引用：`assign` 中指向该 uid 的席位会被移除，其余任务席位不受影响；侧栏计数、席位下拉、空位提示随 `renderAll()` 刷新。
- 招募费按 `state.disciples.peak`（历史峰值）计算，**删除不会降价**，因此不存在「反复招募再删除」刷低价的漏洞；峰值随招募单调上升到 999 封顶。

## 6. 加成公式与接入点

记副属性强度为 `s = power`，主属性强度为 `m = power × MAIN_MULT[tier]`，任务五行为 `E`：

| 情况 | 动作速度 | 经验 / 修为 | 掉落 / 产量 |
| --- | --- | --- | --- |
| 主属性命中（`E === main`） | ×(1 + m) | ×(1 + m) | +m |
| 副属性命中（其余四种） | ×(1 + s) | ×(1 + s) | +s |

原先的「五行不合只给 30% 速度」规则**已失效并删除**：五行齐全后不存在“不合”，改由「主属性 / 副属性」两档替代。

- 动作速度：`actionSpeed(skillId) = speedMul() × (1 + elemBonus(skillId,'speed'))`，直接改变动作计时推进；
- 战斗出手：`calcStats().attackTime = PLAYER_ATTACK_TIME / (1 + elemBonus('combat','speed'))`；
- 经验：`xpMul(skillId)` 末尾乘 `(1 + elemBonus(skillId,'xp'))`，修炼修为同口径；
- 掉落：战斗 / 入世的掉率乘 `(1 + 系数)`；采集 / 炼制 / 观星按系数概率额外 +1 件；
- 灵植：地块为被动生长，不适用速度加成；经验仍按系数提升，收获量按系数概率额外 +1。

例：神品 `s = 6.5%`、`m = 15.6%`：
主属性命中 → 速度 +15.6%（单次耗时约 −13.5%）、经验 +15.6%、产出期望 +15.6%；
副属性命中 → 速度 +6.5%（单次耗时约 −6.1%）、经验 +6.5%、产出期望 +6.5%。
作为对照，v2.9.1 神品单条为 13%：主属性约为其 1.2 倍，副属性约为其 0.5 倍。

## 7. 老存档迁移

`mergeState()` 一次性把旧信徒规范为「五行齐全 + 主属性」：

- **v2.9.1（有 `elems`、无 `main`）**：主属性沿用旧 `elems[0]`（旧属性本就随机，无需重掷）；旧 `power` 先按旧品质区间钳制，再乘 0.5 作为新副属性，主属性由品质倍率导出。
  例：神品旧 `power = 13%` → 新副属性 6.5%、主属性 15.6%；神品旧 `power = 10.4%` → 新副属性 5.2%、主属性 12.48%。旧强度水平一一映射到新区间，不额外膨胀。
- **v2.9.0 及更早（`owned/equipped` 为 id 字符串）**：按目录还原品质，五行补齐、主属性与副属性强度重掷；旧上阵者退回仓库。
- **v2.9.2 及以后**：逐字段校验，非法/越界强度重掷，缺失/重复 uid 重新生成，任务 key 与 uid 必须合法。
- v2.9.1 的 `assign` 只要 uid 仍有效就保留；数量不变、不扣费、不补发资源；总数按招贤殿容量裁剪，读档不会出现 NaN。
- `peak`（招募峰值）缺失时按迁移后的信徒总数兜底；异常/负数按 0 处理，且始终不低于当前仓库数量。

```js
state.disciples = {
  owned: [{ uid, id, tier, elems: [五行齐全], main: 'water', power: 0.065 }, ...],
  assign: { woodcutting: 'uid', combat: 'uid' },  // 任务 key → uid
  peak: 6                                          // 历史招募峰值（只增不减）
}
```

## 8. 界面

- 侧栏「🙏 信徒」副标题：`上阵 n/上阵位 · 信徒 m/容量`。
- 信徒卡片：五个五行徽标全部显示并标注各自强度；主属性徽标加粗高亮并带「主」标，副属性为普通样式；正在驻守的任务对应徽标加虚线描边。
- 任务席位：同样显示五个属性徽标，并按当前任务标出「主属性 / 副属性」；命中主属性的任务，其徽标同时带高亮与描边。
- 任务面板顶部「任务五行」条：显示任务五行、已上阵信徒的五个属性与「主属性命中 · 全效 / 副属性命中 · 全效」状态，并提供跳转信徒面板的按钮。
- 锁妖塔 / 异界裂缝 / 五行裂缝 / 裂缝怪物面板共用「战斗」五行条。
- 信徒面板：招募 → 上阵分配（12 个任务逐行：任务名 + 五行徽标 + 当前信徒 + 主/副状态 + 撤下 + 下拉选择）→ 仓库卡片（五行徽标、品质、主副强度、驻守 / 职位状态、遣散按钮）。
- 担任朝代职位的信徒：任务下拉中不再出现；仓库卡片状态显示「担任「清朝」丞相 · 不可取下」，且不提供撤下按钮。
- 面板骨架只在分配/招募/遣散变化时重建，数值仍走既有 `data-*` 增量刷新。
