# 机制 · 设置与测试控制台

> 版本：v2.6.0 ｜ 配置：`js/data.js` 的 `REDEEM` / `devCodeHash()` ｜ 逻辑：`js/engine.js` 的 `DEV` / `redeemCode()` / `devRun()`
> 入口：侧栏「🔧 设置」→ 兑换码；兑换成功后出现「🔬 测试控制台」

## 1. 定位

- **设置**：为后续设置项提供落位骨架（分组容器 + 占位条目），本次只开放「兑换码」。
- **测试控制台**：给开发/测试用的数值与状态调节面板，**只在本次运行内可用**，不进入正式玩法，也不写入存档。

## 2. 兑换码

### 2.1 配置位置

`js/data.js` 顶部：

- `REDEEM.CODES`：数组，每项 `{ hash, feature, label }`。
- `devCodeHash(str)`：把输入归一化（去首尾空格、转小写、去所有空白）后计算 **FNV-1a 32 位** 哈希，返回 `0x` 前缀的 8 位十六进制。

新增兑换码的流程：把明文码传给 `devCodeHash()`，把得到的 hash 填进 `REDEEM.CODES`。仓库与界面中**不出现明文码**，README/文档也不写出明文。

当前已配置 1 个码，`feature = 'devtools'`、`label = '测试控制台'`。

### 2.2 交互

- 输入框失焦/回车不触发，点击「兑换」按钮执行校验。
- 失败：提示「兑换码无效，请检查后重试。」，红色样式，不产生任何状态变化。
- 成功：`DEV.unlocked = true`，提示转为绿色；侧栏立即出现「🔬 测试控制台」，设置页出现「已解锁」分组。
- 重复兑换同一码：提示「本次运行已解锁测试控制台，无需重复兑换。」
- 校验只影响会话级 `DEV` 对象，不写 `state`，因此**不会随存档导出**。

### 2.3 会话级存储

`js/engine.js`：

```js
const DEV = { unlocked: false, msg: '', msgType: 'info' };
```

- `DEV` 是普通全局常量对象，不在 `defaultState()` / `mergeState()` 中，也就不会被序列化。
- 刷新页面或重开游戏后，`DEV.unlocked` 回到 `false`，控制台入口消失，必须重新兑换。
- 存档里若存在 `ui.active = 'devtools'`（例如异常写入），读档白名单不接受该值，回落到默认面板。

## 3. 测试控制台选项

页面结构：10 个分组、18 行控件；每行「名称 + 当前值 + 输入 + 执行」，改动直接写 `state`，由既有 `renderAll()` / `updateBars()` 反映。

| 分组 | 选项 | 作用 |
| --- | --- | --- |
| 核心资源 | 灵石 / 灵力 / 星砂 / 生命之种 | 直接设为输入值（非负、整数、上限钳制） |
| 洞天资源 | 粮食 / 木材 / 石料（下拉选择） | 写入 `world.res`，受 `worldCap(worldLevel())` 上限约束 |
| 修为与境界 | 境界阶数 1~`TOTAL_STAGES` / 当前修为 | 改 `skills.cultivation.lvl` 或 `xp`，同步重算生命 |
| 技能与精通 | 技能等级 / 精通等级（下拉选技能） | 改 `skills[id].lvl`（1~9999）/ `mastery[id]`（0~`MASTERY_CAP`） |
| 洞天建筑 | 建筑等级（含引力塔） | 写入 `world.buildings`，0 表示删除 |
| 星球 | 灵气浓度 / 穿越次数 | 改 `planet.aura` / `planet.cross` |
| 锁妖塔 | 当前层数 | 改 `tower.current`，并抬高 `best`、清空 pending/failed |
| 三套裂缝 | 异界裂缝：重置 / 标记修复 | `rift = { open, tier }` |
| | 属性裂缝：整轮刷新 / 全部修复 | 复用 `elemRiftSlotsRoll()` 与 `ELEM_RIFT.REFRESH_MS` |
| | 裂缝怪物：重新生成 / 标记击败 | 复用 `riftMonSpawn()`；击败不发放奖励 |
| 时间快进 | 快进秒数 | 调用既有 `simulateOffline(seconds)`，按 0.5s 步长跑 `tick()`，受 `OFFLINE_CAP_H = 12` 小时限制 |
| 存档 | 立即存档 / 重载页面 | 便于验证存档往返与「控制台重新隐藏」 |

实现约束：

- **不在游戏循环里持续跑**：控制台页骨架静态，当前值只在「进入页面」或「执行一次操作」后由 `updateDev()` 填一次（`_devDirty` 标志），不随 `renderAll` 周期写 DOM。
- 快进与结算完全复用 `simulateOffline()` → `tick()`，不另写数值逻辑。
- 所有输入都做 `isFinite` / 非负 / 上限钳制，避免出现 NaN 或负数。

## 4. 存档影响

- 不新增任何持久化字段。
- `mergeState` 的 `ui.active` 白名单新增 `settings`（设置页可以记住），但**不包含** `devtools`。
- 控制台产生的数值改动（灵石、等级等）走的是正常 `state` 字段，**会**随自动存档落盘——这是刻意设计，方便测试后继续观察；若不希望留存，可在控制台点「重载页面」前不存档，或用游戏内的「重开」。

## 5. 渲染与样式

- 设置页：`.setcard` / `.setrow` / `.setin` / `.setmsg`，成功/失败用 `.setmsg.good|bad|warn` 着色。
- 控制台：`.devsec` / `.devrow` / `.devcur` / `.devin` / `.devsel` / `.devgo` / `.devmsg`，≤920px 时标签与输入改为整行堆叠。
- 图标：🔧（U+1F527，Unicode 6.0）、🔬（U+1F52C，Unicode 6.0）。

## 7. 遗留风险

1. **哈希非加密**：FNV-1a 只是避免明文出现，逆向仍可通过穷举猜码；对单机游戏足够，不适合作为联网校验。
2. **控制台改动会落盘**：测试数值随自动存档保留，正式发布前需确认玩家无法获得兑换码（当前码只在开发渠道传播）。
3. **快进受 12 小时上限**：单次最多结算 12 小时，不能用于验证更长的离线场景；这是刻意与线上规则保持一致。
4. **无权限分级**：一旦解锁即拥有全部调试能力，后续若增加更多码，建议在 `REDEEM.CODES` 中加 `scope` 字段区分能力。
5. **设置页目前只有占位分组**：后续新增设置项时，应继续走 `state.ui` + `mergeState` 白名单，避免直接读 `localStorage`。
