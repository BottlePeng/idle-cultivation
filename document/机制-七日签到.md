# 机制 · 七日签到（CHECKIN）

> 侧栏「📅 签到」提供一条低频保底资源线：每天按**本地日期**限领一次，连续 7 天为一轮，
> 第 7 天给一份大赏（含 1 位神品信徒）。签到不占用动作槽、不参与离线结算，也不影响其他任何动作。

## 1. 判定口径

| 项 | 规则 |
| --- | --- |
| 时间源 | 浏览器本地日期 `YYYY-MM-DD`（`checkinDayKey()`），每日本地 00:00 重置 |
| 可领条件 | 今天 ≠ `lastKey`，且今天不早于 `lastKey` |
| 今日已领 | 今天 = `lastKey` → 按钮变为「今日已签到」，拦截再次领取 |
| 时间回退 | 今天早于 `lastKey` → 判定时钟异常，**锁定签到且不动进度**，界面提示校准系统时间 |
| 断签 | 与 `lastKey` 相差 > 1 天 → 下一次领取从第 1 天重新开始（惰性计算，只在领取时写状态） |
| 连续 | 相差 = 1 天 → `day+1`；`day = 7` 领完回到 1 |

判定集中在 `checkinPlan()`（`js/engine.js`），返回 `state` = `ready` / `done` / `clockback`，
以及 `day`（下一次实际可领的天数）、`broken`（是否断签，仅用于界面提示）。`checkinDayDiff()`
按本地 0 点求自然日差，用 `Math.round` 吃掉夏令时带来的 ±1 小时误差。

## 2. 七日奖励（`CHECKIN.DAYS`）

| 天 | 名称 | 奖励 |
| --- | --- | --- |
| 1 | 💠 灵石补助 | 600 灵石 + 聚气丹 ×2 |
| 2 | ✨ 灵息萌发 | 300 灵力 + 生命之种 ×2 |
| 3 | 🎒 行囊补给 | 1500 灵石 + 疗伤丹 ×3 |
| 4 | 💫 观星悟道 | 40 星砂 + 悟道丹 ×1 |
| 5 | 🌱 洞天春耕 | 2500 灵石 + 生命之种 ×5 |
| 6 | 🗡️ 兵甲双全 | 玄铁剑 ×1 + 玄铁甲 ×1 |
| 7 | 👑 七日大赏 | 5000 灵石 + 60 星砂 + 神玉剑 ×1 + **神品信徒 ×1** |

一周总量约 9,600 灵石 + 100 星砂 + 7 生命之种 + 1 悟道丹 + 3 件装备，
相当于一条中前期任务线，不足以冲垮任何资源线，也补不上招贤殿 / 小世界的造价。

奖励字段：`gold` / `spirit` / `stardust` / `seed` / `items[]`（`{ id, qty }`）/ `disciple`（布尔）。

## 3. 领取流程（`claimCheckin()`）

1. `checkinPlan()` 校验：`done` → 日志「今日已签到」；`clockback` → 日志提示校准时间；两种情况都不改状态。
2. **背包格位预检**：只统计「当前尚不持有」的奖励种类（已有物品不占新格），
   若 `新种类数 > 剩余格位` → 整单拒签并提示清理背包，**避免只发一部分奖励**。
3. 依次入账资源与道具，写日志汇总当天所得。
4. 第 7 天额外调用 `checkinTryGrantDisciple()`：
   - 仓库容量 `discipleStoreCap()` 为 0（未建招贤殿）或已满 → 置 `state.checkin.pending = true`，
     日志提示「暂存待入仓」；
   - 成功 → 随机抽 1 位**神品**身份（`DISCIPLE_TIERS[4]`）入仓，不占上阵位、不写招募峰值。
5. 更新 `lastKey = 今天`、`day = day ≥ 7 ? 1 : day + 1`、`total += 1`，立即 `saveState()`。

`checkinFlushPending()` 在主循环 `tick` 中每秒检查一次：仅在 `pending` 为真时做一次容量判断，
腾出招贤殿空位后自动补发并清标记（补发同样不写招募峰值）。

## 4. 存档结构

```js
state.checkin = {
  day: 1,        // 下一次可领的天数（1~7）
  lastKey: '',   // 最近一次领取的本地日期 'YYYY-MM-DD'（'' = 从未领取）
  total: 0,      // 累计签到次数（只增）
  pending: false // 第 7 天神品信徒因仓库满而待补发
}
```

## 5. 旧档迁移与校验（`mergeState`）

| 情况 | 处理 |
| --- | --- |
| 无 `checkin` 字段（旧档） | 默认 `{ day: 1, lastKey: '', total: 0, pending: false }`，即立即可领第 1 天 |
| `day` 非数 / 越界 | 夹到 `[1, CHECKIN.CYCLE]` 并取整 |
| `lastKey` 非法 | 只接受匹配 `^\d{4}-\d{2}-\d{2}$` 的字符串，否则回落到 `''`（视为从未领取） |
| `total` 非法 | 非有限值回落到 0，负数夹到 0 并取整 |
| `pending` | 仅 `=== true` 时保留，其余一律 `false`，避免旧档误触发补发 |

签到状态与动作槽、离线收益完全解耦：读档与 `simulateOffline()` 都不会改写签到进度，
只有 `claimCheckin()` 会写 `day` / `lastKey` / `total`，补发只写 `pending`。
`ui.active` 白名单已包含 `'checkin'`，刷新后仍停留在签到页。

## 6. 界面

- 侧栏按钮「📅 签到」：可领时挂感叹号，并在 `sinfo` 里显示当前是第几天 / 今日已签。
- 面板标题「📅 签到 · 七日循环」，顶部为累计签到次数；7 张日卡按已领取进度标记「已领取 / 今日可领 / 未解锁」。
- 三种提示条：时间回退（红）、断签（黄，「连续签到已中断」）、正常。
- 底部固定说明：本地 00:00 重置、一天一次、7 天一轮、第 7 天领完回到第 1 天。
