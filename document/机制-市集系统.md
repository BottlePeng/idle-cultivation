# 机制 · 市集系统

> 相关代码：`js/data.js`（`SHOPS/shopPrice/findShop/unlockText`）、`js/engine.js`（`buyItem/shopBuy/shopBuyMax/findShopEntry/sellItem/sellPrice`）、`js/ui.js`（`renderShop`）、`js/main.js`（`shopcat/buy/buymax`）

市集参考《梅尔沃放置》的**多商店机制**：按分类分店铺采购，采用**加价购入、折价出售**的价格模型，形成灵石的回流与消耗。v2.13.0 起支持**条件解锁**，并大幅扩充各阶段商品。

---

## 1. 价格模型

| 方向 | 公式 |
| --- | --- |
| **购入价** | 若条目指定 `price` 用其值；否则 `floor(ITEMS[id].value × 1.8)` |
| **出售价** | `max(1, floor(value × 0.55 × (1 + formBonus('sell'))))` |

- **加价 1.8 倍购入 / 折价 0.55 倍出售**：买卖间存在价差，防止「买低卖高」套利，鼓励玩家自产自用。
- 聚宝阵「出售价」阵纹（每级 +2%，上限 +20%）可提高卖价。

`shopPrice(item)`：`item.price` 优先，其次按 `value × 1.8`。

## 2. 条件解锁（v2.13.0）

每个上架条目可选配置 `unlock`，格式与任务 `cond` 共用 `condDone()` 判定：

```js
{ id: 'ore_zi', unlock: { type: 'level', skill: 'mining', lvl: 18 } }
```

| 解锁类型 | 示例 | 含义 |
| --- | --- | --- |
| `level` | `{ type:'level', skill:'woodcutting', lvl:18 }` | 对应技能达到等级 |
| `realm` | `{ type:'realm', stage:27 }` | 境界达到指定阶数 |
| `world` | `{ type:'world', n:60 }` | 洞天建设度达标 |
| `tower` | `{ type:'tower', n:200 }` | 锁妖塔最高层达标 |
| `cross` | `{ type:'cross', n:10 }` | 穿越次数达标 |

界面表现：

- 未解锁条目不隐藏，整卡降低透明度、图标替换为 🔒，名称后显示「需 {条件}」；
- `+1 / +10 / 最大` 三个按钮全部置灰；
- 价格仍然显示，让玩家看到未来目标，但点击无效。

设计理由：

- **不隐藏**：让玩家提前看见成长目标，形成「练技能 → 解锁商品」的正反馈。
- **条件只卡高阶商品**：基础耗材（青鱼、铁矿石等）始终可买，避免早期卡死。
- **引擎兜底**：即使绕过界面（控制台调用），`shopBuy/shopBuyMax` 也会再次校验解锁条件。

### 2.1 同物品跨店规则

同一物品可能出现在多个店铺（如 `ore_iron` 同时在杂货铺与材料行）。`shopBuy` 通过 `findShopEntry(id)` 取第一个**已解锁**的条目：

1. 先按店铺顺序遍历，遇到同 id 且条件已满足的条目立即返回；
2. 若全部未解锁，返回第一个同 id 条目用于给出正确的锁定提示。

因此重复上架不会导致「一个店铺已解锁、另一个店铺仍拒绝」的矛盾。

## 4. 购入（`shopBuy` / `shopBuyMax`）

```
shopBuy(id, qty)
  1. findShopEntry(id) 找到条目
  2. 条目有 unlock 且 condDone 为假 → 提示「尚未解锁」并返回
  3. buyItem(id, qty, shopPrice(entry))

buyItem(id, qty, price)
  1. 物品存在且 qty > 0
  2. 灵石 >= price × qty
  3. 背包可容纳（invCanAdd）
  → 扣灵石、invAdd、写日志
```

界面提供三种购买量：

| 操作 | `data-act` | 行为 |
| --- | --- | --- |
| 买 1 / 买 10 | `buy` | `shopBuy(id, qty)` |
| 买最多 | `buymax` | `shopBuyMax(id)`，按当前金币与单价计算 |

> 背包满时，购入「新种类」会被拒绝（`invCanAdd` 返回 false）。
> 界面按钮的 `disabled` 只是视觉层，引擎侧 `shopBuy/shopBuyMax` 会再次校验，防止误触或脚本调用绕过。

## 6. 界面与交互

- **侧栏「🏪 市集」**：显示「采买 · 出售」摘要。
- **分类切换**：`ui.shopCat`（general / material / pill / equip / farm / premium），由 `shopcat` 事件切换。
- **店铺条目**：图标、名称、说明、单价、解锁状态；提供「买 1 / 买 10 / 买最多」按钮。
- **锁定条目**：`🔒` + 「需 {条件}」，按钮置灰。
- **出售入口**：走背包的出售模式与 popover，不单独设店铺界面。

## 7. 经济循环

```
        ┌──────── 灵石 ────────┐
        │                      │
   采买资源/装备            出售冗余产物
        │                      │
        ▼                      ▲
   投入生产 / 增强战力 ──► 产出更值钱的物品
        │
        └── 突破境界消耗灵石 + 丹药
```

灵石来源：战斗击杀、熔炼提炼、出售物品、任务奖励。
灵石去向：市集采买、境界突破（跨境消耗）、装备获取、**背包扩容**。

### 7.1 与背包扩容的配合

背包扩容是纯灵石回收池（见 [背包系统](./机制-背包系统.md)），不产出任何物品。市集新增商品与扩容条共同承担中后期灵石消耗，避免灵石只进不出：

- 早期：买基础耗材/种子，扩容 2~5 次；
- 中期：买高阶材料补炼器/炼丹缺口，扩容 10~20 次；
- 后期：高阶宝阁与满容量扩容消耗大量灵石，但此时洞天/朝代灵石产出同步提升。

## 8. 扩展指引

- 新增店铺：在 `SHOPS` 追加 `{ id, name, icon, items: [{id, price?, unlock?}] }`。
- 新增上架物品：往对应店铺的 `items` 添加条目；如需统一定价，省略 `price` 让其按 `value × 1.8` 计算。
- 新增解锁条件类型：先在 `engine.condDone` 增加分支，再在 `data.unlockText` 增加文案。
- 若引入「限购 / 补货」机制，需要在 `state` 增加库存字段并在 `mergeState` 迁移。
