# 机制 · 侧栏分组

> 版本：v2.17.0 ｜ 对应代码：`js/data.js`（`SIDEBAR_GROUPS`）、`js/state.js`（`state.ui.sidebarClosed`）、`js/ui.js`（`renderSidebar` / `sidebarEntryMeta`）、`js/main.js`（`sbgroup` 事件）、`css/style.css`（分组与响应式）

## 1. 目标

把原本一路平铺的侧栏入口按功能归组，参考梅尔沃放置的分组侧边栏：

- 分组可点击收起 / 展开；
- 折叠状态持久化，重开游戏保持上次的样子；
- 新增入口只需要「归到某个组」，不修改布局代码；
- 折叠后仍能看到组内有什么（数量 + 图标窥视 + 待处理亮点）；
- 窄屏下不挤坏布局。

## 2. 分组表

配置位于 `js/data.js` 的 `SIDEBAR_GROUPS`，组内数组顺序就是侧栏渲染顺序：

| 组 id | 名称 | 图标 | 入口 |
| --- | --- | --- | --- |
| `main` | 主要 | 📌 | 任务、签到、问道、背包、市集、穿越星球 |
| `cultivate` | 修炼 | 🧘 | 修炼、阵法 |
| `combat` | 战斗 | ⚔️ | 战斗、锁妖塔、战阵 |
| `produce` | 生产 | 🪓 | 伐木、钓鱼、采矿、熔炼、炼器、采药、炼丹、灵植、入世 |
| `world` | 洞天与朝代 | 🏯 | 世界、信徒 |
| `system` | 系统 | 🔧 | 设置、测试控制台（仅本次运行解锁后显示） |

未出现在任何组里的 `SKILL_ORDER` 技能会自动进入运行时的「其他」组，避免新增技能后从侧栏消失。

## 3. 数据驱动扩展

新增一个侧栏入口：

1. 若为技能页：把技能 id 加进 `SKILL_ORDER`（照旧），再把它加进 `SIDEBAR_GROUPS` 某个组的 `items`。
2. 若为特殊页：除加进 `items` 外，在 `js/ui.js` 的 `sidebarEntryMeta(id)` 补一条 `{ name, icon, sub, cls?, bar?, alert? }`。

`renderSidebar` 只遍历 `SIDEBAR_GROUPS`，不包含任何入口级布局代码；组头、窥视图标、折叠行为都由配置推导。

## 4. 折叠状态与存档

- 存档字段：`state.ui.sidebarClosed = { [groupId]: true }`，只记录「已折叠」的组，默认 `{}`（全部展开）。
- 点击组头在 `js/main.js` 的 `sbgroup` case 中切换该组布尔值，并立即 `saveState()`，然后只重绘侧栏（`renderSidebar()` + `updateBars()`），不重建内容面板。
- `mergeState` 只保留 `SIDEBAR_GROUPS` 中仍存在的组 id 且值为 `true` 的项；旧档没有该字段时默认全部展开，删除分组后残留的键会被清掉。
- 折叠状态不放在 DOM、闭包或缓存里，因此 `setHTML` 的签名去重与整树重绘不会覆盖它。

## 5. 与现有渲染机制的配合

| 机制 | 处理方式 |
| --- | --- |
| `setHTML` 签名去重 | 分组 HTML 的 `closed` / `hasactive` 类名参与签名，折叠状态变化会触发重绘 |
| 整树重绘 | 入口按钮仍由 `sidebarEntryHTML(id)` 统一生成，动态副标题每次重绘时重算 |
| `data-bar` 增量刷新 | 技能按钮继续输出 `<span class="sbar" data-bar="id">`，`updateBars()` 不受分组包裹影响 |
| 事件委托 | 组头使用 `data-act="sbgroup" data-id="<组id>"`，与入口的 `data-act="select"` 同级，不需要逐个绑定 |
| 问道高亮 | `applyGuideFocus()` 仍按 `[data-skill]` 查找；目标位于折叠组时，渲染期临时展开该组（不写回存档） |

## 6. 折叠后的可见性

组头始终展示：

- 组图标与组名；
- 该组当前可见入口数量（测试控制台未解锁时按实际可见数计算）；
- 折叠箭头；
- 有入口带待处理标记（任务可领、签到可领、锁妖塔待领、战阵待入库、星球裂缝阻塞、问道未完成）时显示亮点：`hot` / `block` 为橙色并带轻微脉冲，只有 `soft`（问道教学）时为静态蓝点；详细分级见 [提醒视觉](./机制-提醒视觉.md)。

折叠时额外显示「窥视条」：最多 6 个入口图标，超出显示 `+N`。因此折叠不是盲盒。

当前面板所在分组会加 `hasactive` 类，组头文字变为金色，即使组被折叠也能看出当前内容在哪一组。

## 7. 程序化跳转

`sidebarReveal(tab)` 会在以下场景自动展开目标组（只展开这一组，不改变其它组）：

- 问道「前往」；
- 面板内 `goto` 跳转（如星球 → 洞天营造）；
- 打开问道清单；
- 设置页打开测试控制台。

读档时不自动展开当前面板所在组：持久化的折叠状态优先，避免玩家收起的分组在重开后被动打开。

## 8. 响应式

| 宽度 | 行为 |
| --- | --- |
| > 1080px | 组头显示图标 + 名称 + 数量 + 箭头；入口完整显示名称与副标题 |
| ≤ 1080px | 侧栏 78px：组头只留图标 + 数量 + 箭头；入口只留图标；折叠组显示图标窥视 |
| ≤ 820px | 侧栏变为横向滚动条；每个分组是「组头 + 横向按钮」的横向块，折叠组只显示组头；页面不产生横向溢出 |

## 9. 取舍

- **默认全部展开**：保留原有「一眼看到所有入口」的体验；分组只提供整理能力，不强制改变初始布局。
- **折叠状态优先于当前面板**：不在读档时强制展开当前面板所在组，保证「重开保持上次的样子」；通过组头金色高亮提示当前面板位置。
- **问道临时展开不落盘**：教学脉冲需要可见，但不污染玩家手动设置的折叠状态。
- **不引入动画高度计算**：折叠直接用 `display:none`，避免动态内容高度与重绘缓存互相干扰。
