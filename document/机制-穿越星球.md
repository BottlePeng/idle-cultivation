# 机制 · 穿越星球

> 版本：v1.9.9 起生效（v1.9.8 首次引入浓度 / 朝代；v1.9.9 把穿越价格改为灵气浓度并重算上限与恢复）。
> 相关代码：`js/data.js`（`PLANET` / `DYNASTY_NAMES`）、`js/engine.js`（`planetTick` / `planetCross` / `planetAura*`）、`js/ui.js`（`renderPlanet` / `updatePlanet`）、`js/state.js`（存档兜底）。

## 1. 定位

「穿越星球」是一个**占用全局动作槽的主动小游戏**：

- 玩家点击「开启运转」后才会计时、生成、飞行、吸收；切到修炼 / 采集 / 战斗等动作会中断并清空飞行队列。
- 读档后可以停留在星球面板，但**保持未开启**，需要玩家再次点击开启；没有离线星球产出（离线只结算浓度恢复）。
- 本机制不改变原有产物权重与收益内容；v1.9.9 只调整「灵气浓度」这一条资源线。

## 2. 灵气浓度（aura）

灵气浓度是**独立于灵力的第二资源**：巡航时用于生成物品，穿越时作为唯一价格。灵力仍然只负责「吸收」每件 0.5 点，不再参与穿越。

### 2.1 展示格式

面板固定显示：

```
灵气浓度 72.5% (10875/15000)
```

- 百分比 = `floor(当前浓度) / 上限 × 100`，保留 1 位小数。
- 括号里是**同一组整数**的 `当前/上限`，保证百分比与数值换算一致；大于 10 万的数值用 `k/M` 缩写，避免撑爆面板。
- 上限变化（穿越或建引力塔）后，百分比立即按新上限重算；穿越按钮点击后会强制刷新一次，不必等 10Hz 文本节流。

### 2.2 上限与恢复（重算）

```
下一次价格 next = planetCrossCost(cross + 1)
成长系数 scale = next / CROSS_BASE
上限 cap = ceil(max(15000, next × 1.5)) + 100 × 引力塔等级
恢复 regen = (2.0 + 0.5 × 引力塔等级) × scale      // 只有停止运转时才恢复
```

这样设计的原因：

1. **首价 10000 一定装得下**：0 次穿越时 `max(15000, 10000×1.5)=15000`。
2. **后续价格涨多少，上限就涨多少**：上限永远至少是下一次价格的 1.5 倍，不会出现「价格超过上限、永远攒不够」的死锁。
3. **恢复同步放大**：恢复也乘同一个 `scale`，所以每一轮「从空到攒够下一次价格」的时长基本恒定，约为 **5000 秒（83.3 分钟）**（未建塔、停止运转）。建塔后按 `2.0 / (2.0 + 0.5×等级)` 缩短。
4. **引力塔仍然有长期价值**：上限额外 +100/级，恢复额外 +0.5/级，且这两项都继续乘穿越成长系数。

#### 三档实测（0 次穿越）

| 引力塔 | 上限 | 恢复（停止运转） | 起始浓度（30%） | 攒到 10000 还差 | 只挂机等待 |
| --- | --- | --- | --- | --- | --- |
| Lv.0 | 15,000 | +2.0/s | 4,500 | 5,501 | **45.8 分钟** |
| Lv.20 | 17,000 | +12.0/s | 5,100 | 4,901 | **6.8 分钟** |
| Lv.100 | 25,000 | +52.0/s | 7,500 | 2,501 | **0.8 分钟** |

> 「攒到 10000」按 `10000 + AURA_MIN - 起始浓度` 计算，确保扣完仍剩 1。上表是**停止运转**的净恢复；巡航中恢复为 0，净变化是负的（见 2.4）。

#### 穿越次数带来的上限 / 恢复增长（未建塔）

| 当前穿越次数 | 下一次价格 | 上限 | 恢复（停止运转） | 从 1 攒到下一次价格的时长 |
| --- | --- | --- | --- | --- |
| 0 | 10,000 | 15,000 | +2.0/s | 83.3 分钟 |
| 1 | 16,000 | 24,000 | +3.2/s | 83.3 分钟 |
| 5 | 104,857 | 157,286 | +21.0/s | 83.3 分钟 |
| 10 | 769,658 | 1,154,487 | +153.9/s | 83.3 分钟 |
| 20 | 2,134,322 | 3,201,483 | +426.9/s | 83.3 分钟 |
| 50 | 63,944,139 | 95,916,209 | +12,788.8/s | 83.3 分钟 |

> 表中「当前穿越次数」= 已经完成的次数；价格与上限按下一次计算。数值会随引力塔加成继续提高。

### 2.3 单件消耗逐次衰减

```
单件消耗 = max(0.2, round(2 × 0.9^cross, 3))
```

- 第 0 次（初始）：2；第 1 次：1.8；第 2 次：1.62；第 3 次：1.458……
- **下限 0.2**：第 21 次为 0.219，第 22 次起固定 0.2，永远不会降到 0，避免「白嫖」。
- 结果：穿越越多，同样数量的浓度能支撑越久的产出。

固定 **15000 浓度**、基础生成速度（1 件 / 1.8 秒）、**不考虑恢复**时，掉到下限 1 的耗时：

| 穿越次数 | 单件消耗 | 每秒消耗 | 15000 → 1 的耗时 |
| --- | --- | --- | --- |
| 0 | 2 | 1.111/s | 3.75 小时 |
| 1 | 1.8 | 1.000/s | 4.17 小时 |
| 2 | 1.62 | 0.900/s | 4.63 小时 |
| 5 | 1.181 | 0.656/s | 6.35 小时 |
| 10 | 0.697 | 0.387/s | 10.76 小时 |
| 15 | 0.412 | 0.229/s | 18.20 小时 |
| 21 | 0.219 | 0.122/s | 34.24 小时 |
| 22+ | 0.2 | 0.111/s | **37.50 小时** |

> 这张表刻意固定浓度、忽略恢复，只用于验证「衰减」本身：从 3.75 小时到 37.5 小时，续航约 **10 倍**。
> 实际游玩中上限会随穿越次数一起变大，所以真实续航远大于表中值；后期浓度对产出的约束会明显减弱（见「风险与取舍」）。

### 2.4 消耗与恢复的时机

- **消耗发生在生成时**（`planetSpawn` 之前扣当前单件消耗），不是吸收时；已在飞行的物品照常抵达并按灵力结算。
- **巡航中只降不升**：`planetTick` 在运转状态下不恢复浓度；浓度不足以支付「单件消耗 + 1」时停止生成，并在状态栏提示「浓度不足 · 停止运转可恢复」。
- **停止运转后恢复**：不占用动作槽；做其它动作、关闭面板、离线结算都会按 `regen` 恢复，并钳制到上限。
- **为什么改成本次才恢复**：首价是 10000 量级，任何「一直恢复」的速率（≥2/s）都会高于巡航时的单件消耗（约 1.1/s），浓度只会涨不会跌，第 3 条「穿越越多、下降越慢」就完全观察不到。停止运转才恢复，形成清晰的「巡航产出 → 停转回蓝 → 攒够穿越」循环。
- **非零下限**：生成判定为 `aura >= 单件消耗 + AURA_MIN`，扣除后最少仍剩 `AURA_MIN = 1`。浓度不会为负、不会到 0。
- 浓度不足时点击「开启运转」会被拒绝并记录日志，避免玩家开着空转等一个不会来的恢复。

## 3. 穿越与朝代

### 3.1 朝代序列（`DYNASTY_NAMES` + 数值生成）

索引 = 穿越次数，0 为起始朝代：

```
0 清朝 → 1 明朝 → 2 元朝 → 3 宋朝 → 4 唐朝 → 5 南北朝
→ 6 两晋 → 7 三国 → 8 周朝 → 9 商朝 → 10 夏朝
→ 11 古一纪 → 12 古二纪 → … → 20 古十纪 → …
```

夏朝之后由 `planetDynastyName(n)` 按 `n - 11 + 1` 生成「古 N 纪」，不写死有限列表；穿越次数在存档层钳制到 0~10000。

### 3.2 价格曲线（灵气浓度）

- 第 1~10 次：`10000 × 1.6^(n-1)`
- 第 11 次起：在上式基础上再接 `×1.12^(n-10)`
- 常量：`CROSS_BASE=10000`、`CROSS_KNEE=10`、`CROSS_GROW_EARLY=1.6`、`CROSS_GROW_LATE=1.12`、`CROSS_MAX=1e15`（极端次数下防止幂运算溢出为 `Infinity`）。

| 第 n 次穿越 | 价格（灵气浓度） |
| --- | --- |
| 1 | 10,000 |
| 2 | 16,000 |
| 3 | 25,600 |
| 5 | 65,536 |
| 8 | 268,435 |
| 10（夏朝） | 687,194 |
| 11（古一纪） | 769,658 |
| 12（古二纪） | 862,017 |
| 20 | 2,134,322 |
| 30 | 6,628,882 |
| 50 | 63,944,139 |

**推荐理由**：

1. 前 10 次沿用 1.6 的快节奏，首日就能完成「清朝 → 夏朝」的完整体验。
2. 第 11 次起接 1.12 缓坡；n=50 仍是 6394 万，不是 `2^n` 那种天文数字。
3. 上限与恢复都按同一价格曲线放大，所以每一轮等待时间稳定在 83 分钟左右（未建塔），不会越到后期越卡死。
4. 价格只与穿越次数有关，玩家可以清楚预期下一次成本；所有数值集中在 `PLANET` 常量，调平衡只改数据层。

### 3.3 穿越的行为约束

- **只看灵气浓度**：判定为 `aura >= 价格 + AURA_MIN`；成功扣除后 `aura = max(1, aura - 价格)`。不再扣灵力，也不再受眩晕影响。
- 成功时只做三件事：扣浓度、`cross += 1`、重算上限 / 恢复 / 单件消耗。**不重置星球产出、飞行队列、本局收获或加速**，也不占用动作槽。
- 浓度不足时拒绝并记录「需多少 / 当前多少」，不产生任何扣费。
- 穿越不是动作，不参与 `cycleTick` 动作查表，不会与修炼 / 采集 / 战斗产生槽位冲突。

## 4. 界面

星球面板的「朝代 / 穿越」行：

| 元素 | `data-*` | 内容 |
| --- | --- | --- |
| 灵气浓度 | `aura` | `xx.x% (当前/上限)` |
| 浓度提示 | `aurahint` | `单件 −X · 恢复 +Y/s（停止运转）` |
| 当前朝代 | `dynasty` | 清朝 / 明朝 / … |
| 穿越次数 | `cross` | 数字 |
| 穿越按钮 | `data-planetcross` | 浓度不足时 `disabled` + 置灰 |
| 穿越说明 | `crossnote` | 足够：`消耗 💧 N → 下一朝代`；不足：`需 💧 N · 还差 M` |
| 运转状态 | `runstate` | 未开启 / 运转中 / 灵力不足 / 浓度不足 · 停止运转可恢复 |
| 单件消耗 | `auracost` | 面板描述里的当前值 |

- 所有动态值由 `updatePlanet()` 写入 `data-*` 节点；面板骨架只渲染一次，不整树重建。
- 穿越 / 开启 / 停止后会调用 `updatePlanet(true)` 跳过 10Hz 节流，立即刷新百分比、按钮与差额。
- 按钮只切换 `disabled` / class / `textContent`，不重建 DOM。

## 5. 存档兼容

`state.planet` 的长期字段：

| 字段 | 默认值 | 迁移规则 |
| --- | --- | --- |
| `aura` | 上限 × 30% | 旧档（无 `auraVer`）或非有限值 → 新上限 × 30%；否则钳制到 `[1, 上限]` |
| `auraVer` | 1 | 用于识别 v1.9.8 旧档；旧档的 100 上限数值在新体系里没有意义 |
| `cross` | 0 | 非有限值 → 0；否则取整并钳制到 `[0, 10000]` |

- `open` / `items` / `timer` / `boost` / `session` / `waitReason` 仍是瞬态，读档一律重置。
- `planet` 动作本身不被 `mergeState` 恢复，保持「读档停在面板但不自动运转」。
- 浓度与百分比使用同一个 `planetAuraCap()` 和同一组整数，读档后不会出现「百分比与括号数值对不上」。

## 6. 验证要点

- `node --check` 全部 JS。
- 浓度：上限 / 恢复三档、首价攒够时长、百分比与括号一致、上限变化后重算。
- 穿越：首次扣 10000 后剩 1、灵力不变、差 1 点拒绝、连续朝代文本到「古 N 纪」。
- 衰减：0→22 次单件消耗从 2 降到 0.2；固定 15000 浓度掉到下限的耗时从 3.75h 增到 37.5h。
- 门槛：浓度不足按钮置灰并显示差额；足够时按钮可用并显示「消耗 → 朝代」。
- 存档：旧档无 `auraVer` → 30% 新上限；负值 → 1；超上限 → 上限；NaN / 非数字 → 30% 新上限。
- 渲染：连续刷新 30 次 `updatePlanet(true)`，`#content` 直接子节点 childList 变更数为 0。
