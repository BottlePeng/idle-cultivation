# 机制 · 穿越星球

> 版本：v1.9.8 起生效。相关代码：`js/data.js`（`PLANET` / `DYNASTY_NAMES`）、`js/engine.js`（`planetTick` / `planetCross`）、`js/ui.js`（`renderPlanet` / `updatePlanet`）、`js/state.js`（存档兜底）。

## 1. 定位

「穿越星球」是一个**占用全局动作槽的主动小游戏**（见 [动作槽与离线收益](./机制-动作槽与离线收益.md#23-穿越星球主动动作)）：

- 玩家在面板点击「开启运转」后，才会计时、生成、飞行、吸收；切到修炼 / 采集 / 战斗等动作会中断并清空飞行队列。
- 读档后可以停留在星球面板，但**保持未开启**，由玩家再次点击开启；不会自动运转，也没有离线星球收益。
- 本机制在 v1.9.1 引入「灵气浓度 + 穿越朝代」两个新维度，不改变原有的产物权重与收益内容。

## 2. 资源：灵气浓度（aura）

灵气浓度是**独立于灵力的第二资源**，只服务于星球生成，不参与疗伤、突破等其它消耗。

### 2.1 常量（`PLANET`）

| 键 | 值 | 含义 |
| --- | --- | --- |
| `AURA_CAP_BASE` | 100 | 未建引力塔时的浓度上限 |
| `AURA_CAP_GT` | +20 / 级 | 引力塔每级提升上限 |
| `AURA_REGEN_BASE` | 2.0 / 秒 | 基础被动恢复 |
| `AURA_REGEN_GT` | +0.2 / 秒 / 级 | 引力塔每级提升恢复 |
| `AURA_COST` | 2 / 件 | 每**生成** 1 件飞行物扣除的浓度 |
| `AURA_MIN` | 1 | 非零下限；浓度永远不会低于 1 |

上限与恢复随洞天「引力塔」等级成长：Lv.0 为 100 上限 / +2.0 每秒，Lv.20 为 500 上限 / +6.0 每秒，Lv.100 为 2100 上限 / +22.0 每秒。生成吞吐在满加速 + 高引力塔时约 2.2 件/秒（消耗 4.4/秒），后期恢复仍明显富余，因此**不会成为纯卡点**。

### 2.2 消耗、恢复与「不会为零」

- **消耗发生在生成时**（`planetSpawn` 之前扣 `AURA_COST`），不是吸收时；已在飞行的物品照常抵达并按灵力结算。
- **被动恢复**：`planetTick` 每 tick 先恢复浓度，**无论星球是否在运转**都会恢复；不占用动作槽，离线结算同样生效，始终钳制在上限内。
- **非零下限**：生成判定为 `aura >= AURA_COST + AURA_MIN`，扣除后最少仍剩 `AURA_MIN = 1`。浓度不足时**停止生成**（不扣成 0、不出现负数），状态显示「灵气浓度不足，等待中」，恢复后自动继续。
- 选择「非零下限 + 触底停止生成」而不是「纯靠恢复速度不倒空」的原因：
  1. 玩法反馈明确——玩家能看到浓度条见底、生成暂停，而不是资源在后台悄悄变成 0；
  2. 数值安全——任何存档、脚本或边界情况都不可能把浓度写成 0 或负数；
  3. 恢复速率只决定「等待多久」，不承担「永不归零」的正确性，逻辑更简单可验证。
- 该资源**不随开关清空**：`planetReset` 只清飞行队列 / 加速 / 本局收获，`aura` 与 `cross` 属于长期进度，跨会话保留。

## 3. 穿越与朝代

### 3.1 朝代序列（`DYNASTY_NAMES` + 数值生成）

索引 = 穿越次数，0 为起始朝代：

```
0 清朝 → 1 明朝 → 2 元朝 → 3 宋朝 → 4 唐朝 → 5 南北朝
→ 6 两晋 → 7 三国 → 8 周朝 → 9 商朝 → 10 夏朝
→ 11 古一纪 → 12 古二纪 → … → 20 古十纪 → …
```

夏朝之后由 `planetDynastyName(n)` 按 `n - 11 + 1` 生成「古 N 纪」，**不写死有限列表**；N 为 1~99 时用中文数字，更大时用阿拉伯数字（如「古100纪」）。穿越次数本身在 `mergeState` 中钳制到 0~10000，防止异常存档导致幂运算溢出。

### 3.2 价格曲线（推荐值）

用户原公式为 `10000 × 2^n`，n 稍大即失去意义（n=20 已是 52.4 亿，n=50 约 5.6e18）。本实现改为**分段幂律**：

- 第 1~10 次：`1000 × 1.6^(n-1)`
- 第 11 次起：在上式基础上再接 `×1.12^(n-10)`

常量：`CROSS_BASE=1000`、`CROSS_KNEE=10`、`CROSS_GROW_EARLY=1.6`、`CROSS_GROW_LATE=1.12`。

| 第 n 次穿越 | 本方案价格 | 新手 0.2/s | 中期 5.13/s | 后期 24.75/s | 用户公式 `10000×2^(n-1)` |
| --- | --- | --- | --- | --- | --- |
| 1 | 1,000 | 1.4 小时 | 3.2 分 | 0.7 分 | 10,000 |
| 5 | 6,553 | 9.1 小时 | 21.3 分 | 4.4 分 | 160,000 |
| 10（夏朝） | 68,719 | 4.0 天 | 3.7 小时 | 46.3 分 | 5,120,000 |
| 20（古十纪） | 213,432 | 12.4 天 | 11.6 小时 | 2.4 小时 | 5,242,880,000 |
| 50 | 6,394,413 | 370 天 | 14.4 天 | 3.0 天 | 5.63e18 |

> 表中时间按「全部灵力都留给穿越」估算；实际还会被星球吸收（每件 0.5 灵力）与疗伤分流，真实时间略长。

**推荐理由**：

1. **前 3 次 1~2 小时内可完成**：新手 0.2/s 也能在首日体验完整朝代循环，正反馈足够快。
2. **夏朝（第 10 次）累计约 18.2 万灵力**：中期约 9.8 小时、后期约 2 小时，是一个合理的「周目标」；纯挂机上限约 216 万/天，也留有空间。
3. **第 11 次起换 1.12 缓坡**：既保留「越穿越贵」的长期追逐，又避免 `2^n` 在 n=20 之后彻底失去意义；n=50 仍只是百万级，后期 3 天可攒到。
4. **价格只与穿越次数相关**，与境界、建筑无关，玩家可以清楚预期下一次成本；所有数值集中在 `PLANET` 常量，后续调平衡只改数据层。

### 3.3 穿越的行为约束

- `planetCross()`：眩晕中不可穿越；灵力不足则拒绝并记录差额。
- 成功时只做两件事：扣灵力、`cross += 1`，随后按新次数显示朝代。**不重置星球产出、飞行队列、本局收获、加速或浓度**，也不占用动作槽。
- 穿越不是动作，不参与 `cycleTick` 动作查表，因此不会与修炼 / 采集 / 战斗产生槽位冲突。

## 4. 界面

星球面板新增一行「朝代 / 穿越」：

- 当前朝代（`data-pg="dynasty"`）、穿越次数（`data-pg="cross"`）。
- 灵气浓度 `当前 / 上限`（`data-pg="aura"` / `"auracap"`），并附「生成 −2 · 恢复 +X/s · 下限 1」提示（`data-pg="aurahint"`）。
- 「穿越」按钮（`data-act="planetcross"`）：灵力不足时 `disabled` + 置灰，右侧提示「灵力不足，还差 ⚡ N」；足够时提示「消耗 ⚡ N → 下一朝代」。
- 所有动态值由 `updatePlanet()` 按 10Hz 写入 `data-*` 节点，面板骨架只渲染一次，不整树重建；按钮只切换 `disabled` / class / textContent。

## 5. 存档兼容

`state.planet` 新增两个长期字段：

| 字段 | 默认值 | 迁移规则 |
| --- | --- | --- |
| `aura` | 当前上限（旧档视为满浓度） | 非有限值 → 上限；否则钳制到 `[AURA_MIN, 上限]` |
| `cross` | 0 | 非有限值 → 0；否则取整并钳制到 `[0, 10000]` |

`open` / `items` / `timer` / `boost` / `session` / `waitReason` 仍是瞬态，读档一律重置；`planet` 动作本身不被 `mergeState` 恢复，保持 v1.9.7 的「读档停在面板但不自动运转」行为。

## 6. 验证要点

- `node --check` 全部 JS。
- 浓度：生成扣 2、触底停生成且值不低于 1、停止运转后仍恢复、引力塔提升上限与恢复。
- 穿越：第 n 次扣费正确、连续穿越到「夏朝 → 古一纪 → 古十纪」文本正确、灵力不足按钮置灰并显示差额。
- 存档：旧档无 `aura` / `cross` 时给满浓度 / 0 次；读档无负值 / NaN；读档后星球未自动运转。
- 渲染：穿越与运转期间 `#content` 不整树重建。
