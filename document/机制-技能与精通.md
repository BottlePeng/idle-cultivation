# 机制 · 技能与精通

> 相关代码：`js/data.js`（`SKILLS/SKILL_ORDER/xpNeed`）、`js/engine.js`（`addXp/xpMul/masteryOf/addMastery/effTime/doubleChance/masteryGain`）

---

## 1. 技能总览

共 **9 个技能**，各含等级（无上限）与经验。`SKILL_ORDER` 决定初始化与侧栏展示顺序：

```
woodcutting → fishing → mining → crafting → alchemy → combat → cultivation → formation → farming
  伐木          钓鱼       采矿        炼器        炼丹       战斗       修炼          阵法        灵植
```

### 1.1 升级曲线

```
xpNeed(skillId, lvl) = floor(SKILLS[skillId].xpBase × lvl ^ SKILLS[skillId].xpPow)
```

| 技能 | xpBase | xpPow | 定位 |
| --- | --- | --- | --- |
| 伐木 | 25 | 1.55 | 采集 |
| 钓鱼 | 25 | 1.55 | 采集（食物） |
| 采矿 | 28 | 1.55 | 采集 |
| 炼器 | 30 | 1.55 | 配方 |
| 炼丹 | 30 | 1.55 | 配方（丹药+药材采集） |
| 战斗 | 38 | 1.60 | 战斗 |
| 修炼 | 70 | 1.70 | 由境界表接管（见修炼文档） |
| 阵法 | 18 | 1.35 | 辅助 |
| 灵植 | 22 | 1.40 | 辅助 |

> 技能等级**没有硬上限**；`addXp` 内部有单帧 500 级的升级保护。

### 1.2 经验加成（`xpMul`）

```
普通技能：xpMul = (1 + 大境界序号 × 0.06) × 阵法经验加成
修炼技能：xpMul = (1 + 大境界序号 × 6) × (1 + 悟性 × 1%) × 阵法经验加成(修炼组)
```

- **大境界**：每升一个大境界，非修炼技能经验 **+6%**。
- **阵法**：通过 `XP_GROUP` 分通道加成（`cult` / `combat` / `craft` / `gather`），见 [阵法系统](./机制-阵法系统.md)。
  - 伐木/钓鱼/采矿/灵植 → `gather`
  - 炼器/炼丹 → `craft`
  - 战斗 → `combat`
  - 修炼 → `cult`
  - **阵法自身不吃任何阵法经验加成**。

## 2. 精通系统（Mastery）

### 2.1 概念

**精通是「动作级别的独立成长」**：同一个技能下的不同动作各自积累精通，鼓励玩家深挖某条产线而不是盲目跳级。

- 精通对象 id 命名约定：动作 id 本身（如 `wc_qing`、`al_juqi`）；灵植使用虚拟 id `farm_plant` / `farm_harvest`；战斗按怪物 id。

### 2.2 数值

```
精通升级需求：masteryNeed(lvl) = floor(20 × lvl ^ 1.6)
精通经验     ：masteryGain    = max(1, round(动作经验 × 0.6 × (1 + formBonus('mastery'))))
上限         ：MASTERY_CAP = 99
```

### 2.3 精通收益

| 收益 | 公式 | 满级（Lv.99）时 |
| --- | --- | --- |
| 缩短动作耗时 | `× (1 − min(0.20, Lv × 0.002))` | 最多 **−20%** |
| 额外产出概率 | 计入 `doubleChance` | 最多 **+49.5%** |

### 2.4 额外产出（`doubleChance`）

```
doubleChance = clamp( 精通Lv × 0.005 + 技能等级 × 0.002 + formBonus('double'), 0, 0.9 )
```

- 触发时：物品产出 ×2，日志标注「（精通·双倍）」。
- 三路来源叠加：**精通等级**（0.5%/级）+ **技能等级**（0.2%/级）+ **阵法「额外产出」阵纹**。
- 硬上限 **90%**。

### 2.5 动作耗时（`effTime`）

```
effTime(def, id) = def.time × (1 − min(0.20, 精通Lv × 0.002))
```

实际周期推进时还会再乘 `speedMul()`（大境界 + 疾风阵），见 [动作槽文档](./机制-动作槽与离线收益.md)。

## 3. UI 表现

| 位置 | 内容 |
| --- | --- |
| 侧栏技能按钮 | 图标 + 名称 + `Lv.N` + 等级进度条 |
| 面板头部（`skillHeader`） | 技能说明 + 等级与经验条 |
| 动作条目 | 单次耗时、经验、产出，以及该动作的**精通等级徽标** |
| 配方条目 | 材料需求（不足高亮）、产出、精通等级 |
| 增量刷新 | `updateXpText()` / `updateXpBars()` 只更新 `data-xp` / `data-xpbar` 节点 |

## 4. 扩展指引

新增一个受技能成长影响的行为时：

1. 在 `SKILLS` + `SKILL_ORDER` 登记技能（若是新技能）。
2. 动作类对象放入 `ACTIONS`（无消耗）或 `RECIPES`（有消耗）。
3. 结算时调用 `addXp(skillId, amount)` 与 `addMastery(actionId, amount)`。
4. 若需消耗材料随精通降低，可在 `effTime` 逻辑外单独处理（当前未启用）。

> **注意**：精通 id 与动作 id 绑定；删除动作时，`mergeState` 会裁剪对应的 `state.mastery` 条目（为避免脏数据，动作下线需同步清理）。
