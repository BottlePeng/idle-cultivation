# 机制 · 锁妖塔

> 版本：v2.1.0 ｜ 代码入口：`TOWER` / `state.tower` / `startTower` / `towerClaim` / `renderTower`
>
> 锁妖塔是「无尽层 + 单场战斗 + 先领奖再进层」的挑战系统。它复用现有战斗的命中 / 闪避 / 减伤 / 出手节奏与战败逻辑，不另建战斗引擎；占用全局唯一动作槽，不产生离线收益。

---

## 1. 定位与入口

- **入口**：侧栏「锁妖塔」按钮，位于「战斗」之后。
- **面板**：显示当前层、最高已通关层、状态、该层妖物属性、挑战 / 领奖按钮、本层奖励预览、里程碑与成长公式。
- **核心循环**：

```
挑战第 N 层 → 实时战斗（占用动作槽）
   ├─ 击败 → pending = N（可领奖），动作槽立即释放
   │      └─ 点击领取 → 发放奖励，current = N+1，pending = false
   └─ 阵亡 → 本次失败，层数不降、不产生 pending，可原地重试第 N 层
```

- **不重置**：`current` 与 `best` 写入存档，停止挑战、切换面板、关闭游戏、读档都不清零。系统没有「重置层数」入口。

## 2. 逐层推进

每层是一场独立战斗，敌人属性只由层数决定，同一层反复挑战 / 预览完全一致。

设 `f` = 层数，`t = f - 1`：

| 属性 | 公式 | 说明 |
| --- | --- | --- |
| 生命 | `round(26 × (1 + 0.30t + 0.010 × t^1.9))` | 幂律 + 线性，早期平缓、后期加速 |
| 攻击 | `round(5~9 × (1 + 0.03t + 0.005 × t^1.5))` | 低于生命成长，避免高层秒杀 |
| 命中 | `14 + 2.0t` | 与玩家闪避同步线性 |
| 闪避 | `8 + 1.2t` | 玩家命中率保持在 50%~95% 区间 |
| 减伤 | `min(0.35, 0.02 + 0.004t)` | 上限 35%，不再压低玩家输出 |
| 出手间隔 | `max(1.8, 2.8 - 0.002t)` | 下限 1.8 秒，防止高频连击 |

**与玩家成长曲线的匹配**：

- 玩家战斗属性大致随战斗等级线性增长（攻击 `5+2×(Lv-1)`、生命 `60+8×(Lv-1)`、防御转减伤上限 75%）。
- 塔内每层发放战斗经验 `38 × f^1.75`，玩家通关层数越高、战斗等级跟进越快，形成「层数 ↔ 等级」互相追赶。
- 在最保守模型（无装备、无阵法、无洞天、无信徒、无境界加成，每层满血开始）下实测：
  - 第 1 层约 22 秒、第 10 层约 15 秒、第 50 层约 53 秒、第 500 层约 137 秒；
  - 第 491 层首次出现随机阵亡（3 次内通过），1~500 层全部可通关，没有「第 3 层就打不过」或「第 500 层仍是秒杀」。
- 真正的理论瓶颈出现在 500 层之后：敌方攻击按 `f^1.5` 增长，而玩家生命只随等级近似 `f^1.06` 增长，长期会被敌方 DPS 追上。届时需要装备、阵法、洞天、信徒与境界加成补足；当前版本未对 500 层之后做专项平衡。

## 3. 奖励

### 3.1 结构

| 奖励 | 公式 / 规则 |
| --- | --- |
| 灵石 | `round(12 × f^1.7) × (f%5==0 ? 2.5 : 1) × (1 + formBonus('gold') + worldBonus('gold'))` |
| 星砂 | `max(1, round(1.2 × f^0.9)) × (f%5==0 ? 3 : 1)` |
| 战斗经验 | `round(38 × f^1.75)`，走 `addXp('combat')`，正常吃经验加成 |
| 丹药 | 每 5 层必掉 1 颗；每 10 层再追加 1 颗。按层数分档（疗伤丹 → 聚气丹 → 筑基丹 → … → 混沌丹） |
| 材料 | 每 10 层追加，数量 `1 + floor(f/50)`；按层数分档（灵石原矿 → 冰晶石 → … → 无虚根） |

- **里程碑**：每 5 层为里程碑，灵石 ×2.5、星砂 ×3、必掉丹药；每 10 层额外追加材料。
- **领取制**：击败后只进入 `pending`，点击「领取」才实际入库；领取后 `pending` 清空、层数 +1，同一层无法重复领取。
- **预览**：面板实时显示 `pending || current` 层的奖励，数值与领取时完全同口径（含灵石加成）。
- **背包保护**：领取前预检背包槽位，材料 / 丹药没有新槽位时整单拒绝，不会静默丢奖励。

## 4. 动作槽与失败

### 4.1 单一动作槽

- 挑战时 `state.action = { skill: 'tower', id: 'floor' }`，与战斗、星球、生产动作共用同一槽位。
- 开始挑战会 `planetInterrupt()` + `cancelCombat()`，中断星球与普通战斗 / 秘境。
- 切换到伐木、钓鱼、修炼、星球、普通战斗、秘境等任意动作时，`combatTick` 检测到动作槽已不属于塔，立即 `cancelCombat()`，塔内目标与计时全部清空。
- 塔战用 `state.skills.combat` 的同一套目标 / 计时字段，但额外用 `c.tower = 层数` 标记；`cancelCombat()` 会同时清 `c.tower`，避免历史上「战斗动作未注册导致无法中断」的问题。
- 不产生离线收益：读档时 `mergeState` 丢弃 `c.tower` 与塔内目标；若存档动作是 `tower`，动作槽直接置空，不会在离线结算中继续打塔。

### 4.2 阵亡

- 沿用现有战斗死亡逻辑：生命置 1、死亡计数 +1、停止动作、清除战况。
- 锁妖塔不降层：`current` 不变、`pending` 不产生，仅置 `failed` 供面板显示「已阵亡 · 可重试」。
- 玩家疗伤后可再次挑战同一层；重试开始时 `failed` 清除。

## 5. 存档

```js
state.tower = {
  current: 1,      // 当前层（1 起）
  best: 1,         // 最高已通关层；通关时取 max(best, floor)
  pending: false,  // false 或「待领取层数」
  failed: false    // 仅界面瞬态，读档不恢复
};
```

- 读档兜底：无 `tower` 字段 → `current=1 / best=1 / pending=false`。
- 非法值钳制：`current`、`best` 夹到 `1 ~ TOWER.MAX_FLOOR`；`pending` 必须是数字且等于 `current`，否则置 `false`。
- `best` 收敛：`best = max(best, current - 1)`，允许当前层领先最高已通关层 1 层。
- 不复用 `planet` / `rift` / `dungeons` 字段；旧档与无字段存档均可正常启动。
- 挑战途中读档：塔战是瞬态，不恢复目标与计时；`current` 保持挑战前数值，无残留战斗状态。

## 7. 风险与后续

- **高层节奏**：300 层后单层需要 100~140 秒；作为无尽挑战可以接受，但若希望「刷塔」更轻量，可考虑加入扫荡 / 连战（当前未做）。
- **无排行榜**：`best` 只存本地，未做跨玩家排行。
- **500 层后平衡**：未专项验证；敌方攻击成长最终会超过玩家生命成长，需要装备 / 阵法 / 境界补足，或后续增加塔内专属成长。
- **奖励通胀**：高层灵石与经验奖励很大，可能让常规战斗与市集收益显得偏低；后续可按需调整 `GOLD_POW / XP_POW`。
- **随机阵亡**：高层的命中 / 伤害浮动可能导致偶发失败，这是设计内的挑战成本；失败不降层，不会造成永久卡关。
